- 극단적인 예시로 Logic만을 활용하여 같은 결과를 수행하게 만들 수 있으며, 이벤트만 사용해서 같은 결과를 만들 수 있습니다.
- 그러나 메이플스토리 월드에서는 이벤트와 Logic을 구분하여 사용할 수 있게 제작했습니다.

## Event와 Logic의 차이

<p align="center">
<img src="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Adventure/MSW-100_Adventure_7_001.png" alt="MSW-100_Adventure_7_001.png">
</p>

- 이벤트와 Logic의 가장 큰 차이는 요청을 누가 처리하는지의 차이가 있습니다.
- Event
    - 사건이 발생하는 순간, 사건의 주체가 직접 요청을 수신하고 이를 처리합니다.
    - 대표적인 예시로 플레이어의 체력이 감소했을 경우, UI의 업데이트와 같은 형식이 Event를 사용하는 방식입니다.
- Logic
    - 직접적으로 기능을 수행하는 Logic을 스크립트에서 호출하여 사용합니다.
    - 기능을 수행하는 Logic을 직접 호출하므로 직관적이며 처리의 순서를 직접 제어할 수 있습니다.

<br>

### Event란?

<p align="center">
<img src="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Adventure/MSW-100_Adventure_7_002.png" alt="MSW-100_Adventure_7_002.png">
</p>

> Gemini로 제작된 AI 이미지입니다.

- 게임을 플레이하면 다양한 상황들이 발생합니다.
- 이러한 상황들이 각각의 **Event**가 됩니다.
    - Event의 예시
        - 플레이어가 적에게 맞았을 경우
        - 플레이어가 체력 회복 아이템을 사용한 경우
        - 플레이어가 몬스터를 처치했을 경우
        - ETC
- 특정한 사건이 일어났을 때, 해당 사건이 일어났음을 외치는 것이 Event입니다.

### ☑️ Logic으로도 구현할 수 있는데 Event를 왜 사용하나요?
<p align="center">
<img src="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Adventure/MSW-100_Adventure_7_003.png" alt="MSW-100_Adventure_7_003.png">
</p>

> Gemini로 제작된 AI 이미지입니다.

- 프로그래머에게 가장 어려운 부분은 변화하는 요구 사항을 개발해야 하는 일입니다.
- 하지만 시스템이 경직적이고 유동성이 없다면 새로운 기능을 요구할 때 마다 시스템을 고쳐야 하는 문제가 발생하게 됩니다.
- Logic을 활용하여 개발할 경우 직접적으로 기능을 호출하기 때문에 확실한 기능의 처리를 보장받을 수 있지만 필요한 처리가 늘어나면 그만큼 수정해야 하는 양 역시 늘어나게 됩니다.

### Logic으로 UI를 처리하는 경우

```lua
@Component
script PlayerBattleComponent extends Component

@EventSender("Self")
handler HandleHitEvent(HitEvent event)
-- 만약 플레이어가 몬스터에게 맞았을 경우 체력 UI 업데이트, 효과음 출력, 화면 이펙트를 출력합니다.
_UIHPLogic.UpdateLife()
_SoundLogic.PlayEffect(event.PlayEffectSound)
_ScreenEffectLogic.PlayHitEffect()
end

end
```

> 해당 코드는 Plain Text로 작성된 코드입니다. 예시를 위해 작성된 코드로, 샘플 월드에서는 사용하지 않는 코드입니다.

- Logic으로 처리할 경우 각각의 기능을 담당하는 Logic을 호출해야 합니다.
- 그러나 추후 다른 시스템, 기능이 추가될 때 마다 해당하는 Logic을 찾아서 등록해야 합니다.
- 또한 같은 기능을 수행하는, 다른 캐릭터도 동일한 기능이 필요할 경우 모든 Script를 찾아서 등록해야 합니다.
- 이럴 경우, 매번 모든 기능들을 찾아서 등록해야 하는 문제가 발생합니다.

### Event로 UI를 처리하는 경우
```lua
@Component
script PlayerBattleComponent extends Component

property number currentHP = 0

@EventSender("Self")
handler HandleHitEvent(HitEvent event)
-- 만약 플레이어가 몬스터에게 맞았을 경우 맞았다는 이벤트를 발생합니다.
local localPlayerHitEvent = LocalPlayerHitEvent()
self.currentHP = self.currentHP - event.Damages
localPlayerHitEvent.RemainHP = self.currentHP
self.Entity:SendEvent(localPlayerHitEvent)
end

end
```

> 해당 코드는 Plain Text를 기준으로 작성된 코드입니다. 예시를 위해 작성된 코드로, 샘플 월드에서는 사용하지 않는 코드입니다.

- 플레이어가 피격되었을 때 이벤트를 담당하는 Logic을 모두 호출하는 대신, **LocalPlayerHitEvent** 이벤트를 발송합니다.
- 플레이어가 "나 맞았어! 너무 아파!"라고 시스템 전체에게 소리치는 상태입니다.

```lua
@Logic
script UIHPLogic extends Logic

@EventSender("LocalPlayer")
handler HandleLocalPlayerHitEvent(LocalPlayerHitEvent event)
local playerRemainHP = event.RemainHP
-- playerRemainHP는 현재 플레이어의 남은 체력이므로 이에 맞춰 UI를 업데이트합니다.
end

end
```

> 해당 코드는 Plain Text를 기준으로 작성된 코드입니다. 예시를 위해 작성된 코드로, 샘플 월드에서는 사용하지 않는 코드입니다.

- 플레이어의 이벤트를 수신받은 **UIHPLogic**이 전달받은 남은 체력을 기준으로 HP UI를 업데이트합니다.
- 이외에 SoundLogic, ScreenEffectLogic도 각각의 Event Handler에 LocalPlayerHitEvent를 등록하고 필요한 처리를 수행하도록 기능을 제작합니다.
- 이렇게 제작된 코드는 추후 추가적인 기능을 제작하더라도 LocalPlayer만 바라보면 기능을 추가로 제작할 수 있습니다.

## Event와 Logic의 문제점
<p align="center">
<img src="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Adventure/MSW-100_Adventure_7_004.png" alt="MSW-100_Adventure_7_004.png">
</p>

- 그러나 Event와 Logic 모두 개별의 문제점을 가지고 있습니다.
- Event의 문제점
    - Event는 처리 담당자 중 누가 먼저 Event를 수신하는지 알기 어렵습니다.
    - 따라서 절차적으로 기능이나 연산을 수행해야 하는 경우, 절차가 보장받을 수 없습니다.
    - Event의 파편화로 인해 Logic을 사용하는 것 보다 더 많은 Event를 관리해야 할 수 있습니다.
- Logic의 문제점
    - 기능이 추가될 때 마다 해당 기능을 사용해야 하는 모든 Script에 Logic을 호출하도록 기능을 제작해야 합니다.
    - 이로 인해 하나의 Component가 수많은 Logic을 알아야 하는 강한 연결성을 가지게 되는 문제가 발생합니다.

<br>

## Event와 Logic의 적절한 분배
- 따라서 Event와 Logic을 사용할 때 적절한 분량으로 이를 분배해야 합니다.
- 아래는 대표적인 예시입니다.
    - Event를 사용하는 경우
        - UI업데이트와 같이 Client에서 기능이 수행되는 경우
    - Logic을 사용하는 경우
        - 데미지 연산, 플레이어의 경험치 총량 계산 등 값의 연산이 이뤄지는 경우

<br>

## 최소 구현 기준
- Event를 활용하여 UI의 업데이트는 Event로 처리하도록 기능을 리팩토링합니다.
- Logic을 활용하여 값의 연산이 이뤄지는 항목을 처리하도록 기능을 구현합니다.

## 응용 및 확장 방향
- Logic화 된 항목을 추후 Server와 연동될 수 있도록 Method의 실행 환경을 설계합니다.
- Event는 Logic이 서버에서 값을 받아오면 이에 따라 Client에서만 구동되는 UI가 업데이트 될 수 있도록 기능을 설계합니다.
