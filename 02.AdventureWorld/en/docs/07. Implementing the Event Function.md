## Event System
- You can use either event or Logic to create the same end result.
- As an extreme example, you can only utilize Logic to execute the same result, and you can use only event to create the same end result.
- However, MapleStory Worlds was created so that event and Logic can be differentiated and used separately.

<br>

## The Difference Between Event and Logic

<p align="center">
<img src="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Adventure/MSW-100_Adventure_7_001_en.png" alt="MSW-100_Adventure_7_001_en.png">
</p>

- The biggest difference between event and Logic is who processes the request.
- Event
    - The moment the incident is triggered, the subject of the incident receives the request directly and processes it.
    - The prime example is when the player's HP is decreased, a format like UI updates utilizes Event.
- Logic
    - Call the Logic that directly executes the function from the script for use.
    - Since the Logic that executes this function is called directly, it is direct, and the processing order can be controlled as well.

<br>

### What is an Event?

<p align="center">
<img src="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Adventure/MSW-100_Adventure_7_002.png" alt="MSW-100_Adventure_7_002.png">

> This is an AI image created with Gemini.

- Various situations can occur in-game.
- These situations each become an **Event**.
    - Example of an Event
        - When the player gets hit by an enemy.
        - When the player uses an HP recovery item.
        - When the player defeats a monster.
        - Etc.
- An Event is what declares something has happened when a certain incident occurred.

<br>

### ☑️Why use an Event when you can just use Logic?
<p align="center">
<img src="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Adventure/MSW-100_Adventure_7_003.png" alt="MSW-100_Adventure_7_003.png">
</p>

> This is an AI image created with Gemini.

- One of the hardest jobs of a programmer is to develop a changing request.
- However, if the system is rigid and has no flexibility, then they will run into the issue of having to fix the system every time a new function is required.
- Using Logic for development means you will be directly calling the function, which guarantees the function's processing. But when the number of required processes increases, the amount of work increases at a commensurate rate.

### When Having to Process UI with Logic

```lua
@Component
script PlayerBattleComponent extends Component

@EventSender("Self")
handler HandleHitEvent(HitEvent event)
-- Updates the HP UI, plays sound effects, and outputs screen effects if the player gets hit by a monster.
_UIHPLogic.UpdateLife()
_SoundLogic.PlayEffect(event.PlayEffectSound)
_ScreenEffectLogic.PlayHitEffect()
end

end
```

> This code is written with Plain Text. This is example code and isn't used in sample world.

- When processing with Logic, you need to call the Logic that manages each function.
- However, when another system or function is added, you need to find the relevant Logic and register it.
- Also if there is a need for the same function for another character that does the same thing, you need to find all of the Script and register as needed.
- In this case, all functions need to be searched each time for registration.

### When Having to Process UI with Event
```lua
@Component
script PlayerBattleComponent extends Component

property number currentHP = 0

@EventSender("Self")
handler HandleHitEvent(HitEvent event)
-- Triggers a hit-event when the player is hit by a monster.
local localPlayerHitEvent = LocalPlayerHitEvent()
self.currentHP = self.currentHP - event.Damages
localPlayerHitEvent.RemainHP = self.currentHP
self.Entity:SendEvent(localPlayerHitEvent)
end

end
```

> This code is written based on Plain Text. This is example code and isn't used in the sample world.

- Instead of calling all of the Logic that manages the event when the player is hit, the **LocalPlayerHitEvent** is sent out.
- The player is currently yelling out "I've been hit! It hurts!" to the entire system.

```lua
@Logic
script UIHPLogic extends Logic

@EventSender("LocalPlayer")
handler HandleLocalPlayerHitEvent(LocalPlayerHitEvent event)
local playerRemainHP = event.RemainHP
-- The UI is updated based on playerRemainHP, which represents the current player's remaining HP.
end

end
```

> This code is written based on Plain Text. This is example code and isn't used in the sample world.

- The HP UI is updated based on the remaining HP that was received by **UIHPLogic**, which receives the player's event.
- Additionally, SoundLogic and ScreenEffectLogic register LocalPlayerHitEvents to each Event Handler and create functions that are needed for processing.
- Code created in this way allows you to additionally create functions simply by looking at LocalPlayer in the future.

## The Cons of Event and Logic
<p align="center">
<img src="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Adventure/MSW-100_Adventure_7_004_en.png" alt="MSW-100_Adventure_7_004_en.png">
</p>

- However Event and Logic Both have their own unique issues.
- Cons with Event
    - It's hard to tell which managing processor received the Event first.
    - So when following a sequential process or calculation, that process can't be guaranteed.
    - You may need to manage more Events than the amount of Logic used due to Event fragmentation.
- Cons with Logic
    - Each time a new function is added, you will need to create a function that calls all Logic to all the Scripts that use that function.
    - This causes the issue of a single Component needing to know numerous Logics through a powerful linked connection.

<br>

## The Appropriate Distribution of Event and Logic
- So when using Event and Logic, you should adequately distribute the use of both of them.
- The following is a prime example.
    - When Using Event
        - When the function is executed by the Client like with the UI update.
    - When Using Logic
        - When calculations are taking place, such as damage calculations and player's total EXP.

<br>

## Minimum Implementation Standards
- Refactor the function using Event so that the UI update is handled by Event.
- Implement a function that uses Logic to process items that need the calculation of values.

## Usage and Extension Direction
- Set-up an execution environment for Method so that items that have been Logic-ed can be linked to the Server.
- Set-up a function so that when Logic receives values from the server, Event will only update the UI that is only operated in Client.
