- The offline reward is a function that accumulates rewards even when the player doesn't have the world launched.
- It is a device that entices players to log back in to the world by giving the player rewards so that their characters can be come stronger.

<br>

### Creating Logic
- A Logic that manages currency and a Logic that distributes rewards based on time in order to implement the offline rewards.
- The sample world created them as **GameLogic** and **TimeRewardLogic**.
- The following is the code for **GameLogic** and **TimeRewardLogic**.

```lua
@Logic
script GameLogic extends Logic

property number summonToken = 0

property boolean needTimer = false

property number maxLeftTime = 10.0

property number leftTimeDelta = 0

@ExecSpace("ClientOnly")
method void NeedResult()
-- Determines whether the current map is InGame.
if _UserService.LocalPlayer.CurrentMapName == "InGame" then
	-- Searches for and assigns MonsterSpawnController if in an InGame state.
	local MonsterSpawnController = _EntityService:GetEntityByPath("/maps/InGame/MonsterSpawnController")
	local monsterSpawnComponent = MonsterSpawnController.MonsterSpawnController
	local userId = _UserService.LocalPlayer.PlayerComponent.UserId
	monsterSpawnComponent:ChangeResultUI()
	-- Saves the current wave and the highest wave to variable.
	local currentWave = monsterSpawnComponent.waveIndex
	local bestWave = _DataStorageLogic.clientBestWave
	-- Only saves when the current wave achieved is larger than the previous Wave.
	if currentWave > bestWave then
		_DataStorageLogic:RequestSaveBestWave(userId, currentWave)
		-- Updates the client value immediately after the update.
		_DataStorageLogic.clientBestWave = currentWave
		bestWave = currentWave
	end
	-- Compares the Wave reached and the saved Wave and hands it over, so it can be sent to the UI.
	_UIManageLogic:ShowResultUI(currentWave, bestWave)
end
end

@ExecSpace("ClientOnly")
method void RestartGame()
-- Determines whether the current map state is InGame.
if _UserService.LocalPlayer.CurrentMapName == "InGame" then
	-- Searches for MonsterSpawnController based on the path and registers it.
	local MonsterSpawnController = _EntityService:GetEntityByPath("/maps/InGame/MonsterSpawnController")
	local monsterSpawnComponent = MonsterSpawnController.MonsterSpawnController
	-- Requests the function that needs to be executed by MonsterSpawnController when the game restarts.
	monsterSpawnComponent:CallRestart()
    -- Searches for and registers characterSlotPosGroup.
	local characterSlotController = _EntityService:GetEntityByPath("/maps/InGame/CharacterSlotPosGroup")
	local characterSlotGroupComponent = characterSlotController.CharacterSlotGroupComponent
	-- Deletes all characters that are child entities for characetrSlotGroupComponent.
	characterSlotGroupComponent:ClearCharacterList()
    -- Changes summonTokken to 1 to make it so that game play is possible if summonTokken is currently 0 or lower.
	if self.summonToken <= 0 then
		self:UpdateSummonTokken(1)
	end
	self:DisableTimer()
end
end

@ExecSpace("ClientOnly")
method void OnBeginPlay()
-- Requests the offline reward and applies it.
self:CallOfflineReward()
-- Loads the local player's ID value and then pre-loads the target user's highest record.
local userId = _UserService.LocalPlayer.PlayerComponent.ProfileCode
_DataStorageLogic:RequestLoadBestWave(userId)
end

@ExecSpace("ClientOnly")
method void CallOfflineReward()
-- Requests offlineReward and applies it.
local getUserID = _UserService.LocalPlayer.PlayerComponent.ProfileCode
self:RequestOfflineReward(getUserID)
end

@ExecSpace("Server")
method void RequestOfflineReward(string UserID)
-- Requests the last login time.
_TimeRewardLogic:LoadLastLoginTime(UserID)
end

@ExecSpace("ClientOnly")
method void UpdateSummonTokken(number ChangeValue)
-- Updates SummonTokken with the received value and then updates UI.
self.summonToken = self.summonToken + ChangeValue
_UIManageLogic:UpdateSummonTokken(self.summonToken)
end

@ExecSpace("ClientOnly")
method void NeedTimer()
-- Converts to a state that requires a timer and makes a request, so the timer is functional.
self.needTimer = true
self.leftTimeDelta = self.maxLeftTime
end

@ExecSpace("ClientOnly")
method void DisableTimer()
-- Defeats all of the enemies in the wave and changes it to a state that doesn't need a timer.
self.needTimer = false
_UIManageLogic:DisableTimer()
end

@ExecSpace("ClientOnly")
method void OnUpdate(number delta)
-- Starts Timer if needTimer is true.
if self.needTimer then
	-- Starts the game over processing when leftTimeDelta is 0 or lower.
	if self.leftTimeDelta <= 0 then
		self.needTimer = false
		self.leftTimeDelta = 0
		_UIManageLogic:UpdateTimer(self.leftTimeDelta)
		self:NeedResult()
	else
		-- Executes time decrease and UI processing if there is any time left.
		self.leftTimeDelta = self.leftTimeDelta - delta
		if self.leftTimeDelta <= 0 then
			self.leftTimeDelta = 0
			end
			_UIManageLogic:UpdateTimer(self.leftTimeDelta)
	end	
end
end

end
```

```lua
@Logic
script TimeRewardLogic extends Logic

property string storageKey = "LastLoginTime"

@Sync
property number offlineReward = 0

@Sync
property boolean offlineRewardComplete = false

@ExecSpace("ServerOnly")
method void SaveCurrentTime(string userId)
    local currentTime = os.time()
    local userDataStorage = _DataStorageService:GetUserDataStorage(userId)
    
    -- Saves the current os.time() value as a key named "LastLoginTime".
    userDataStorage:SetAsync(self.storageKey, tostring(currentTime), function(errorCode, key)
        if errorCode == 0 then
            log(userId .. "'s login time was successfully saved: " .. currentTime)
        else
            log("Save failed! Error Code: " .. errorCode)
        end
    end)
end

@ExecSpace("ServerOnly")
method void LoadLastLoginTime(string userId)
local userDataStorage = _DataStorageService:GetUserDataStorage(userId)
    
userDataStorage:GetAsync(self.storageKey, function(errorCode, key, value)
if errorCode == 0 then
	-- If there is no previously-saved time, the value could be nil.
	local lastTime = tonumber(value) or 0
            
	-- Calls the calculation logic that was already created to get the reward stats.
	self.offlineReward = self:CalculateTimeReward(lastTime)
	-- Saves the current time, since the reward has been claimed.
	self:SaveCurrentTime(userId)
	end
end)
end

@ExecSpace("ServerOnly")
method number CalculateTimeReward(number lastLoginTime)
-- Compares the last login time and the current time, calculates the required reward, and distributes it.
self.offlineRewardComplete = true
if lastLoginTime == nil or lastLoginTime == 0 then
	return 1
end

local currentTime = os.time()
local timeDiff = currentTime - lastLoginTime

if timeDiff < 0 then 
	timeDiff = 0 
end
	
if timeDiff <= 1 then
	return 1
else
	-- Distributes 1 additional SummonTokken every 10 seconds.
	local returnValue = math.floor(timeDiff / 10)
	-- Proceeds with processing to distribute only up to 10.
	if returnValue >= 10 then
		returnValue = 10
	end
    return returnValue
end
   
end

@ExecSpace("ClientOnly")
method void OnSyncProperty(string name, any value)
-- Updates SummonTokken if the offlineReward value has been changed.
if name == "offlineReward" then
	_GameLogic:UpdateSummonTokken(value)
end
end

end
```

> This code is written based on Plain Text.

- The sample world gives 1 token for every 10 seconds not spent logged in, up to a max of 10.
- The resulting value calculated by **TimeRewardLogic** is input to summonTokken from **GameLogic**.
- The player can then summon characters based on the summonTokken status.

## ⚠️ Notes for Implementing Offline Rewards
- **Security and Exploits**
    - If the user manually sets the device's clock to the future, it will consider that much time has passed, which can lead to distributing a large amount of rewards to them.
- **Game Economy and Balance**
    - The game's economy may crumble of there isn't a set Max Cap to the offline rewards after implementing them.
- **Ratio and Decimal Point Processing**
    - Assuming that 10 gold is given per minute, there could be an issue if a player logs back in only 30 seconds after their last log in.
- **Time Zone Problem**
    - If the player travels overseas, the subsequent change of time due to differing time zones may lead to too much rewards given out or no rewards given out.
- **User Experience and Exception Processing**
    - If the game has a limit to the inventory, some offline rewards may be lost if there are more rewards than available slots.
    - Data may get lost when the game is force-closed or if the connection to the network is lost while claiming rewards.

### Possible Solutions
- The following are potential solutions to the problems listed above.
- **Security and Exploits**
    - There is a way to prevent the client from intervening by making it so that value processing is only handled by the server.
- **Game Economy and Balance**
    - You can create a Max Cap to the rewards to prevent too much of the rewards being awarded.
- **Ratio and Decimal Point Processing**
    - This is an issue from the design stage, so when making a rule, special care needs to be taken to ensure exceptions don't happen.
- **Time Zone Problem**
    - You can use Coordinated Universal Time (UTC) to prevent such issues.
- **User Experience and Exception Processing**
    - Proceed with exception processing to check if there's enough space before distributing the rewards.
    - If network communication is needed, you can check whether communication has failed. And if it has failed, you can repeat the request 2–3 more times to reduce communication errors.
