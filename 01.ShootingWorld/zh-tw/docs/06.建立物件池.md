## 什麼是物件池？
- 在進行遊戲時，會存在大量實體。
- 在這些實體中，像怪物這樣的單位有時會死亡並消滅。
- 但若單位數量很多，建立並消滅所有單位的行為會對電腦運算造成負擔。
- 但若事先建立實體，並不是消滅而只是停用，就能減少電腦負擔。
- 因為就像打開或關閉開關一樣，只要設定On、Off即可。
- 物件池會預先建立實體，再傳遞可使用的實體，以將不必要的產生與消滅工作降到最低。
<br>

## 製作物件池
- 為了製作物件池，必須在Map內建立實體。
- 以範例世界為基準，InGame地圖中的ProjectileManager被當作用來管理投射體的物件池使用。
- 物件池由如下Component構成。

- **TransformComponent**：這是預設提供的Component。但為了能在地圖內正確位置出現，必須將Position值設為0。
- **ProjectileManager**：這是為了製作物件池而新增的Component。由於該Component必須自行製作，因此必須透過New Component來製作。
<br>

## 設定ProjectileManager元件

- 必須如下撰寫程式碼。
- 該程式碼是在Plain Text環境下撰寫。

```lua
@Component
script ProjectileManager extends Component

property table projectilePool = {} -- 用於存放投射體實體的table。

@ExecSpace("ClientOnly")
method Entity GetMissile(string MissileKey)
-- 若沒有以請求的MissileKey作為Key值的要素，則嘗試初始化。
if self.projectilePool[MissileKey] == nil then
	self.projectilePool[MissileKey] = {}
end

-- 以MissileKey為Key，將projectilePool中的要素登錄到Pool中。
local pool = self.projectilePool[MissileKey]
-- 將用於儲存可使用實體的entity設為nil。
local entity = nil

-- 若pool中有要素存在，則開始搜尋。
if #pool > 0 then
	-- 搜尋pool中的要素。
	for i = 1, #pool do
		-- 若第i個實體存在，且目前使用狀態為false，則回傳該實體。
		if isvalid(pool[i]) and not pool[i].Enable then
			entity = pool[i]
			break
		end
	end
end

-- 若目前entity仍為nil，表示不存在可用實體，因此嘗試產生。
if entity == nil then
	-- 依據MissieKey值向DataTableLogic請求投射體資料。
	local missileData = _DataTableLogic:GetMissileDataByMissileID(MissileKey)
	-- 透過SpawnService建立投射體。
    entity = _SpawnService:SpawnByModelId(missileData.ModelRUID, missileData.MissileID, Vector3.zero, self.Entity)
	-- 在建立的投射體中登錄投射體資料。
	entity.MissileComponent:InitData(missileData)
	-- 將自己登錄為投射體的poolManager。
	entity.MissileComponent.poolManager = self
	-- 將投射體的使用狀態變更為true。
	entity.Enable = true
	-- 將建立的實體登錄到projectilePool。
	table.insert(self.projectilePool[MissileKey], entity)
else
    -- 由於存在可使用的實體，因此將找到的實體使用狀態變更為true。
    entity.Enable = true
end
-- 回傳找到或建立的實體。
return entity
end

@ExecSpace("ClientOnly")
method void ReturnMissile(Entity missile)
-- 若傳入的實體為不可使用狀態，則立即結束程式碼。
if not isvalid(missile) then return end
-- 將傳入實體的使用狀態設為將傳入實體的使用狀態設為false。
missile.Enable = false
end

@ExecSpace("Client")
method void ResetPool()
-- 以自己本身的實體為基準尋找子實體。
local childList = self.Entity.Children
-- 若沒有子實體，則return。
if childList == nil then return end
-- 逐一巡覽找到的子實體清單，將實體的Enable改為false。
for i, child in pairs(childList) do
	if isvalid(child) then
		child.Enable = false
	end
end
end

@ExecSpace("Client")
method Entity GetProjectileSkill(string SkillKey)
-- 若projectilePool中不存在以SkillKey為Value的值，則嘗試初始化。
if self.projectilePool[SkillKey] == nil then
	self.projectilePool[SkillKey] = {}
end

-- 將以SkillKey為Key的要素登錄到pool中。
local pool = self.projectilePool[SkillKey]
-- 將用於回傳的entity設為nil。
local entity = nil

-- 若pool中有要素存在，則開始搜尋。
if #pool > 0 then
	-- 搜尋pool中的要素。
	for i = 1, #pool do
		-- 若第i個實體存在，且目前使用狀態為false，則回傳該實體。
		if isvalid(pool[i]) and not pool[i].Enable then
			entity = pool[i]
			break
		end
	end
end

-- 若pool中沒有可用的技能投射體實體，則新建實體。
if entity == nil then
	-- 以SkillKey為基準，向DataTableLogic請求資料。
	local skillData = _DataTableLogic:GetSkillDataBySkillID(SkillKey)
	-- 透過SpawnService請求建立投射體技能Model。
    entity = _SpawnService:SpawnByModelId(skillData.ModelRUID, skillData.SkillID, Vector3.zero, self.Entity)
	-- 請求輸入投射體技能的資料。
	entity.ProjectileSkillComponent:InitData(skillData)
	-- 將建立的實體登錄到projectilePool。
	table.insert(self.projectilePool[SkillKey], entity)
end
-- 將要回傳的實體使用狀態變更為true。
entity.Enable = true
-- 回傳找到或建立的實體。
return entity
end

end
```

- 先前撰寫的PlayerState與MonsterState都參照了ProjectileManager。
- PlayerState是透過ConnectMissilePool，MonsterState則是透過FindProjectileManager來尋找。
- 透過這種方式，Player與Monster都可以透過物件池發射投射體。
<br>

## 最低實作標準
- 利用物件池功能，實作讓投射體實體不會反覆建立與消滅。
- 投射體建立請求不由玩家或Monster自行提出。
- 所有投射體都以從物件池產生或回傳可使用實體的形式來實作。
<br>

## 應用與擴展方向
- 修改程式碼，讓其符合物件池**預先建立**後使用的原則。

- 實作功能，讓物件池只會預先建立必要的實體。
