## Managing Stages in Defense World
- To provide users with a variety of stages, the game environment must be configured for each stage number.
- A middle manager is needed to serve as an intermediary, responsible for overseeing individual stage numbers and stage configurations.
- Create **StageLogic** using globally-accessible **Logic** scripts within your program. 

<br>

### Creating StageLogic
- StageLogic fulfills the following roles.
  - currentStage: Records the current stage number the player will proceed to.
  - StageReset: In the proper Maingame, initialize the game environment to match the current stage number.
  - OpenNextStage: Performs the function of allowing the user to move on to the next stage after clearing the stage.
  - SetStageBackGround: Sets the background for the current stage.

<br>

- Write the following code.
- The target code is based on Plain Text.
```lua
@Logic
script StageLogic extends Logic

property integer currentStage = 1 -- Records the number of the current stage.

property boolean isStageStart = false -- Indicates whether the current stage is in progress.

property string backGroundEntityPath = "/maps/MainGame/Background" -- Records the path to the BackGround entity.

@ExecSpace("ClientOnly")
method void StageReset()
-- Function that sets the current stage to restart from the beginning.

-- Set to disable the Results screen popup.
_UI_Result:Hide()

-- Save the player's baseComponent.
local myBase = _EntityService:GetEntityByPath("/maps/MainGame/MyBase").BaseComponent
-- Store the enemy's baseComponent.
local enemyBase = _EntityService:GetEntityByPath("/maps/MainGame/EnemyBase").BaseComponent

-- Activates the player's base entity.
myBase.Entity.Enable = true
-- Activates the enemy's base entity.
enemyBase.Entity.Enable = true

-- Ensure that all units produced from the player's baseComponent are returned to the object pool.
myBase:ReturnAllUnit()
-- Ensure that all units produced from the enemy's baseComponent are returned to the object pool.
enemyBase:ReturnAllUnit()

-- Initializes the player's baseComponent.
myBase:Init()
-- Initializes the enemy's baseComponent.
enemyBase:Init()
-- Set the BackGround for the stage.
self:SetStageBackGround()
-- Set the stage as in progress.
self:SetStageState(true)

-- Set the Stage Number UI Text at the top.
_UI_MainGame:UpdateStageNumberText()
end

@ExecSpace("Client")
method void OpenNextStage()
-- A function that switches to the next stage.

-- Check the number of all stages.
local totalStageCount = #_DataSetLogic.stageData

-- If the stage is a lower stage than the last stage,
if totalStageCount > self.currentStage then
	-- Increase the number of the current stage by 1.
	self.currentStage += 1
	-- Record the user's last cleared stage number in data storage.
	_GameLogic:SaveLastStage(self.currentStage)
end

-- Reverts the stage state back to its initial state.
self:StageReset()
end

@ExecSpace("ClientOnly")
method void SetStageState(boolean isStart)
-- Function that changes the current state of the stage.

-- If parameter 1 isStart: true, the stage is in progress.

-- Records the state of the stage as an internal member.
self.isStageStart = isStart
end

@ExecSpace("ClientOnly")
method void SetStageBackGround()
-- Function to switch the background.

-- Access the entity that manages the BackGround recorded as an internal member to access the BackgroundComponent.
local backGroundComponent = _EntityService:GetEntityByPath(self.backGroundEntityPath).BackgroundComponent
-- Sets the background element to the background for the current stage number.
backGroundComponent:ChangeBackgroundByTemplateRUID(_DataSetLogic.stageData[self.currentStage].BackGroundRUID)
end

end
```

## Switching Maps Using TeleportService
<p align="Center">
<img src="../../_images/MSW-100_Defense_5_001.png" alt="MSW-100_Defense_5_001"
</p>

- On the Title screen, the user must enter the MainGame map registered in the **Hierarchy** in order to complete battle preparation and enter the game in earnest.

<br>
<br>

<p align="Center">
<img src="../../_images/MSW-100_Defense_5_002.png" alt="MSW-100_Defense_5_002"
</p>

- Move the character entity that the game screen output is based on from the **Title** map to the **MainGame** map so that you can properly proceed with the game.
- To move character entities to another map, you need to utilize the TeleportService, a feature provided by MapleStory Worlds.
- The TeleportService for map transitions can be used as follows.
```lua
[server only]
void TeleportToMainGameMap(Entity playerEntity)
{
    -- Register the path to the MainGame map entity registered in the Hierarchy.
    string destinationPath = "/maps/MainGame"

    -- Passes the target entity and path value received as parameters to the function. 
    -- Moves the target to a child of the entity placed at destinationPath.
    _TeleportService:TeleportToEntityPath(playerEntity,destinationPath)
}
```

### Creating TeleportLogic
- TeleportLogic utilizing Defense World's TeleportService is created as follows.
- The target code is based on Plain Text.

```lua
@Logic
script TelePortLogic extends Logic

property string localPlayerName = "" -- The variable to hold the name of the player entity that appears when the world runs.

@ExecSpace("Server")
method void SaveLocalPlayerNametoServer(string userName)
-- This function registers the entity name of the local player on the server side.

-- Parameter 1 userName: Takes in the entity name of the character being controlled by the local player.

-- Records the parameter (player entity name) as an internal member.
self.localPlayerName = userName
end

@ExecSpace("ServerOnly")
method void TelePort(string mapName)
-- Function that performs the Teleport function.

-- Parameter 1 mapName: Receives the name of the map you want to move to.

-- Finds and records the target player entity that you have registered as an internal member.
local playerEntity = _UserService:GetUserEntityByUserId(self.localPlayerName)

-- Declare a variable to hold the value of the path to the map you want to move to.
local mapPath = ""

-- If the parameter's value is 'Title', then
if mapName == "Title" then
	-- Set the value of mapPath as shown below.
	mapPath = "/maps/Title"

-- If the parameter's value is 'MainGame', then	
elseif mapName == "MainGame" then
	-- Set the value of mapPath as shown below.
	mapPath = "/maps/MainGame"

-- If an invalid parameter value is received,
else
	-- Set the error values shown below to be output to the log.
	-- log_error("Invalid map name. Please check again.")
end

-- If the target player entity and map path are set, perform a map switch using the TeleportService function.
_TeleportService:TeleportToEntityPath(playerEntity,mapPath)
end

end
```

## Checking Map Transition Point Using HandleEntityMapChangedEvent
<p align="Center">
<img src="../../_images/MSW-100_Defense_5_003.png" alt="MSW-100_Defense_5_003"
</p>

- In order to proceed with the stage, the **StageReset** function in **StageLogic** must be called to initialize each stage after the transition to the MainGame map.
- If the StageReset function is called simultaneously with the execution of the Teleport function, a synchronization mismatch may occur.
  1. If a **StageReset** is performed at the same time as a teleport, it may cause problems when performing operations that link entities, references, etc. registered within the **MainGame** map.
  2. You can avoid issues like this by calling the **StageReset** function after the teleport operation has been requested and the map has fully transitioned. 

<br>

## Finding Local Player Using UserService
<p align="Center">
<img src="../../_images/MSW-100_Defense_5_004.png" alt="MSW-100_Defense_5_004"
</p>

- The UserService allows you to find the local player in the user's client environment.

```lua
[client only]
void OnBeginPlay()
{
  local playerEntity = _UserService.LocalPlayer
}
```
<br>

⚠️ Since the local player cannot be accessed from within server-managed functions, in order to identify or control a specific player on the server side, you must directly receive the player's entity from the client.

## Register ButtonComponent's Click Event
<p align="Center">
<img src="../../_images/MSW-100_Defense_5_005.gif" alt="MSW-100_Defense_5_005"
</p>

- In order to enter the proper game from the Title map, an interaction that actually switches maps when the player presses Start Game is needed.
- Within the **OnBeginPlay** function that is called when the world is launched, pre-register the ability to switch to the **MainGame** map using the ButtonComponent's Event functionality. 

```lua
Linking the functionality of buttons in UI_Title Logic

Property:
-- Assign the button entity to a variable and establish the reference in advance.
[None]
Entity gameStartButton = /ui/Title/GameStartButton

Method:
[clientOnly]
void OnBeginPlay()
{
  -- When target entity button click event occurs utilizing the Entity's ConnectEvent function, connect to call the EnterMainGame function.
  self.gameStartButton:ConnectEvent(ButtonClickEvent,self.EnterMainGame)
}

[server]
void EnterMainGame()
{
  _TelePortLogic:TelePort("MainGame")
}
```

## Minimum Implementation Standards
- Clicking the 'Start Game' button on the Title screen should teleport you to the MainGame map without any errors.
- When a stage is cleared, currentStage is increased by 1, and the game must restart completely with the next stage's data (background, enemy information).
