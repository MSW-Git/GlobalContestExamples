## Registering TriggerComponent
<p align="Center">
<img src="../../_images/MSW-100_Defense_3_001.png" alt="MSW-100_Defense_3_001"
</p>

- TriggerComponent needs to be able to detect when it is in proximity to an opponent's unit.
- When a collision (in range) between an opponent's unit and your TriggerComponent's Collider is detected, the TriggerComponent's event functionality can be utilized.

<br>

### Scoping the Collider
<p align="Center">
<img src="../../_images/MSW-100_Defense_3_002.png" alt="MSW-100_Defense_3_002"
</p>

- You need to set the Collider size and range of the unit to detect the opponent's TriggerComponent.
  - BoxSize: You can set the size of the collision box by assigning values for the X, Y axis.
  - ColliderOffset: Sets the position of the center point of the collision box away from the entity reference point.
  - Collider: Can visually see the assigned range and set the Size or Offset value by dragging or dropping the mouse.
- If the Collider range is too large, units can behave as if they are attacking from a distance.

<br>

### Setting Collision Groups
- Since the player-created units should only attack the opponent's units or bases, we need to make sure that they can only detect the opponent's Collider through the TriggerComponent.

### Adding Collision Groups

### Setting the Collision Matrix

<p align="Center">
<img src="../../_images/MSW-100_Defense_3_004.png" alt="MSW-100_Defense_3_004"
</p>

- Units created by the players will have their CollisionGroup set to 'Player', and in the Matrix, Player will not detect collisions between Player units.
- Units spawning from enemy bases set their CollisionGroup to 'Enemy' to enable the Matrix to detect collisions between Player and Enemy.

## Handling Unit Death Animation
<p align="Center">
<img src="../../_images/MSW-100_Defense_3_006.gif" alt="MSW-100_Defense_3_006"
</p>

- If a unit's HP drops to 0 or below after taking a hit, the entity should be removed or disabled after the death animation plays.
- If you remove an entity at the same time as a 'DEAD' state transition is taking place with a CustomState component registered to the unit, you may experience issues with the animation not playing.

<br>

### HandleSpriteAnimPlayerEndFrameEvent
- If you utilize the SpriteAnimPlayerEndFrameEvent provided by the SpriteRendererComponent, you can call its event function when the last frame is played that ends the animation.

```lua
Example of utilizing the HandleSpriteAnimPlayerEndFrameEvent event function of the CustomState component.

Property:

string currentState = ""



Event Handler:

[self]
HandleSpriteAnimPlayerEndFrameEvent(SpriteAnimPlayerEndFrameEvent event)
{
    -- An event function that is called when the last frame of the currently-playing animation is reached.
    
    -- If the current unit's state is "DEAD" (the situation in the last frame of the DEAD animation)
    if self.currentState == "DEAD" then
        -- Deactivates your own entity.
        self.Entity.Enable = false
    end
}
```

## Minimum Implementation Standards
- A TriggerComponent must be registered to perform interactions between units.
- Because player-produced units must attack enemy units, and enemy units must attack player-produced units, the TriggerComponent's Maxtrix setting is required.

<br>

## Usage and Extension Direction
- You can add a defense stat to a unit's stats to add a separate process for calculating the damage value delivered when hit.
- You can set up a Matrix to add confusion to your units, giving them the ability to attack ally units.
