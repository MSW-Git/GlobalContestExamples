## What is an Object Pool?
- Many entities are used when executing the game.
- Of those entities, bullets or platforms that are spawned frequently must be removed from the screen after a set time. 
- However, spawning and destroying entities takes up memory, and when those processes repeat over a short window of time, it could cause the computer to be overwhelmed (frame drops).
- However, if the activation is removed instead of creating and eliminating entities, it can lower the load on your computer.
- This is because the memory is used and reused like flipping a switch.
- In other words, Object Pools are a key optimization technique that minimizes unnecessary creation and destruction by holding pre-created entities in a "pool" and pulling them out and returning them when needed.

## Creating Object Pool to Store Units
- Declare the unitPool property, which is an empty table that will serve as the **Pool**.
- Create as many units as the parameter using CreateUnit(createCount) function.
- Utilize SpawnService to clone entities from the original unit model.
- Since this is not a unit that will be used right away, disable it by setting **Enable = false** and store it in the **Pool** table.
- The following code demonstrates the process of pre-pooling unit entities ahead of time.

```lua
Preparing five units in the unitPool when the world is run.

Property:
-- Declare the Pool where the units will be stored and managed.
[None]
table unitPool = {}
-- Declare a parent entity variable where the inactive unit entity will be held on the hierarchy.
[None]
Entity tempUnitParent

Method:
[clientOnly]
void OnBeginPlay()
{
    -- Pre-generate 5 units when the world runs.
    CreateUnit(5)
}

[clientOnly]
void CreateUnit(integer createCount)
{
    local unitModelEntryID = "Original Model Entry ID"
    tempUnitParent = "The parent entity in the hierarchy used to store deactivated entities"

    -- Performs a loop with the parameter createCount number of times.
    for i = 1, createCount, 1 do
        -- Creates a new entity from the original model using SpawnService.
        local newUnit = _SpawnService:SpawnByModelId(
            unitModelEntryID, 
            "UnitName", 
            Vector.zero, 
            tempUnitParent
            )

        -- Leave the created unit entity inactive.
        newUnit.Enable = false
        -- Save the newly-created unit entity in the Pool table where units are stored.
        table.insert(self.unitPool,newUnit)
    end
}
```

## Get Units From the Object Pool
- The GetUnit(parent) function is called when a unit is needed.
- The parameter, parent, causes the unit entity to be activated and registered as a child entity of the **parent** entity.
- First, if there are units available in the unitPool, return the unit entity being held.
- If none are available, create a new unit and have it returned.
- To pull a unit from a table, utilize the **table.remove** function.
- When placing the pulled entity, move it to the parent (AttachTo) and then enable it with **Enable = true** to put it into the game.

```lua
Receiving a unit from BaseComponent

[clientOnly]
void SpawnUnit(string unitName)
{
    -- Receive a unit entity from the object pool.
    local unit = _ObjectPoolLogic:GetUnit(self.Entity)
    -- Sets the location of the unit entity to the location of the spawn point.
    unit.TransformComponent.Position = self.spawnLocation.TransformComponent.Position
    -- Accesses the UnitComponet of the Unit and initializes it.
    unit.UnitComponent:Init(unitName,self.isUser)
}
```

```lua
Workflow of the GetUnit Function in ObjectPool Logic

Method:
[clientOnly]
Entity GetUnit(Entity parent)
{
    -- If there are no more entities registered in the unitPool,
    if #self.unitPool <= 0 then
        -- Create a new unit entity.
        self:CreateUnit(self.initCreateCount)
    end

    -- Returns the last element in unitPool(table), removing it from the table.
    -- ---@type Entity: Specifies the type of the variable in question.
    ---@type Entity
    local tempUnit = table.remove(self.unitPool,#self.unitPool)

    -- Sets the parent of the unit entity retrieved from the pool to the provided entity.
    tempUnit:AttachTo(parent)
    -- Since this unit entity will be used, change the Enable setting to true to enable.
    tempUnit.Enable = true

    -- Returns the entity element.
    return tempUnit
}
```

## Returning Units
- The ReturnUnit(unitEntity) function is used to return a unit that has run out of HP or has ended its role back to the pool without destroying it.
- Set up internal functions to immediately stop physical collision, movement operations on unit entities.
- Put the entities back into the **unitPool** via **table.insert**.
- Disable the entity itself with Enable = false and change the parent to a queue entity (PoolParent) to make it invisible to the screen. 

```lua
Process of Returning Units

Method:
[clientOnly]
OnDamage(integer damage)
{
    self.hp -= damage

    if self.hp <= 0 then
        _ObjectPoolLogic.ReturnUnit(self.Entity)
    end
}
```

```lua
Workflow of the Return Function in ObjectPool Logic

Method:
[clientOnly]
ReturnUnit(Entity unitEntity)
{
    -- Disables the functionality of the RigidbodyComponent registered with the returning unit.
    unitEntity.RigidbodyComponent.Enable = false
    -- Register the passed entity to unitPool.
    table.insert(self.unitPool,unitEntity)
    -- Disable Enable, since utilizing the entity is done.
    unitEntity.Enable = false

    local unitPoolParentEntity = _EntityService:GetEntityByPath("/maps/MainGame/ObjectPool/UnitPool")

    -- Transfer the parent entity of the returning unit back to PoolParent.
    unitEntity:AttachTo(unitPoolParentEntity)
}
```

- The code for ObjectPool Logic is written as follows.
- The target code is based on Plain Text.

```lua
@Logic
script ObjectPoolLogic extends Logic

property integer initCreateCount = 5 -- The number of creation upon initialization for each pool element.

property table unitPool = {} -- The pool in which to manage units.

@ExecSpace("ClientOnly")
method void CreateUnit(integer createCount)
-- Function that creates the specified number of unit entities to unitPool and add to unitPool(Table).

-- Parameter 1 createCount: Creates as many new Unit entities as received and adds them to the pool.

-- Records the EntryID value of the Model that is the source of the unit to be created.
local unitModelEntryID = "model://a8b9e5f1-0f95-4031-a2d9-47cda943aa9f"
-- The parent entity where Unit entities disabled from the Hierarch will be stored. 
local unitPoolParentEntity = _EntityService:GetEntityByPath("/maps/MainGame/ObjectPool/UnitPool")

-- Performs a loop as many times as the passed parameter (createCount).
for i = 1, createCount, 1 do
	-- Utilize SpawnService to create (clone) a Unit model.
	local tempUnitEntity = _SpawnService:SpawnByModelId(unitModelEntryID,"Unit",Vector3.one * 1000, unitPoolParentEntity)
	-- Disable the entity, because it's not going to be used right away.
	tempUnitEntity.Enable = false
	-- Register the unit entity created in unitPool.
	table.insert(self.unitPool,tempUnitEntity)
end
end

@ExecSpace("ClientOnly")
method Entity GetUnit(Entity parent)

-- Function to retrieve the Unit entity.

-- Parameter 1 parent: Set the parent of the entity you wish to receive as the parameter entity.

-- If there are no more entities registered in the unitPool,
if #self.unitPool <= 0 then
	-- Create a new unit entity.
	self:CreateUnit(self.initCreateCount)
end

-- Returns the last element in unitPool(table), removing it from the table.
-- ---@type Entity: Specifies the type of the variable in question.
---@type Entity
local tempUnit = table.remove(self.unitPool,#self.unitPool)

-- Sets the parent of the unit entity retrieved from the pool to the provided entity.
tempUnit:AttachTo(parent)
-- Since this unit entity will be used, change the Enable setting to true to enable.
tempUnit.Enable = true

-- Returns the entity element.
return tempUnit
end

@ExecSpace("ClientOnly")
method void ReturnUnit(Entity unitEntity)
-- Returns the active unit back to the pool.

-- Parameter 1 unitEntity: Receives the unitEntity to return.

unitEntity.RigidbodyComponent.Enable = false
-- Register the passed entity to unitPool.
table.insert(self.unitPool,unitEntity)
-- Disable Enable, since utilizing the entity is done.
unitEntity.Enable = false

local unitPoolParentEntity = _EntityService:GetEntityByPath("/maps/MainGame/ObjectPool/UnitPool")

-- Transfer the parent entity of the returning unit back to PoolParent.
unitEntity:AttachTo(unitPoolParentEntity)
end

@ExecSpace("ClientOnly")
method void ClearUnitPool()
self.unitPool = {}
end

end
```

## Minimum Implementation Standards
- Return logic should be implemented to keep the entity in the table in an inactive state without destroying it.
- Unit requests should include exception handling that checks inside the pool (table) and dynamically creates additional entities if insufficient.

## Usage and Extension Direction
- Manage different kinds of pools: You can create and manage dedicated pools not only for units, but also for frequently created and destroyed elements such as projectiles, damage text on hit, and more.
- Build a system where you only prepare a small amount at the beginning and increase the pool's storage limit as the wave progresses and the number of enemies increases.
