## 什麼是物件池?
- 在遊戲進行中會使用大量實體。
- 其中，像子彈或平台這種會頻繁生成的要素，過一段時間後就必須從畫面上消失並被銷毀。 
- 但是生成(Spawn)與銷毀(Destroy)作業會伴隨記憶體配置與釋放，因此如果這個過程在短時間內反覆進行，就會對電腦運算造成很大負擔(掉幀)。
- 但若事先建立實體，並不是消滅而只是停用，就能減少電腦負擔。
- 因為它是像開關一樣，只切換狀態並重複利用記憶體。
- 也就是說，物件池(Object Pool)是一種核心最佳化技法，它會把預先建立的實體放進「水池(Pool)」中，需要時再取出使用並返還，藉此將不必要的生成與銷毀降到最低。

<br>

## 建立儲存Unit的物件池
- 宣告作為**Pool**角色的空表格unitPool屬性。
- 透過CreateUnit(createCount)函式生成參數數量的英雄。
- 運用SpawnService，從原始英雄模型複製實體。
- 因為不是要立即使用的英雄，所以設定為**Enable = false**並停用後，儲存於**Pool**表格。
- 下列程式碼撰寫了預先在Pool中準備英雄實體之過程的範例程式碼。

```lua
世界執行時在unitPool中預先準備5個英雄的過程

Property:
-- 宣告英雄會被儲存、管理的Pool。
[None]
table unitPool = {}
-- 宣告停用中英雄實體在Hierarchy上儲存的父實體變數。
[None]
Entity tempUnitParent

Method:
[clientOnly]
void OnBeginPlay()
{
    -- 世界執行時預先生成5個英雄。
    CreateUnit(5)
}

[clientOnly]
void CreateUnit(integer createCount)
{
    local unitModelEntryID = "原始模型Entry ID"
    tempUnitParent = "停用中的實體在Hierarchy上儲存的父實體"

    -- 依參數createCount次數執行反覆敘述。
    for i = 1, createCount, 1 do
        -- 運用SpawnService從原始模型生成新實體。
        local newUnit = _SpawnService:SpawnByModelId(
            unitModelEntryID, 
            "UnitName", 
            Vector.zero, 
            tempUnitParent
            )

        -- 停用生成的英雄實體。
        newUnit.Enable = false
        -- 將生成英雄的實體儲存至Pool表格。
        table.insert(self.unitPool,newUnit)
    end
}
```

## 從物件池取得英雄
- GetUnit(parent)函式會在需要英雄時呼叫。
- 參數parent為英雄實體啟用後登錄為**parent**實體的子實體。
- 若unitPool中有可使用的英雄，則回傳保存中的英雄實體。
- 若沒有可使用的英雄，則新生成英雄並回傳。
- 從表格取出英雄時，會運用**table.remove**功能。
- 配置取出的實體時，會移動(AttachTo)到parent後，以**Enable = true**啟用並投入遊戲。

```lua
BaseComponent接收英雄的過程

[clientOnly]
void SpawnUnit(string unitName)
{
    -- 從物件池接收英雄實體。
    local unit = _ObjectPoolLogic:GetUnit(self.Entity)
    -- 將英雄實體位置設定為生成點位置。
    unit.TransformComponent.Position = self.spawnLocation.TransformComponent.Position
    -- 存取Unit的UnitComponet並進行初始化。
    unit.UnitComponent:Init(unitName,self.isUser)
}
```

```lua
ObjectPool Logic的GetUnit函式動作過程

Method:
[clientOnly]
Entity GetUnit(Entity parent)
{
    -- 若unitPool中已無登錄的實體，
    if #self.unitPool <= 0 then
        -- 生成新的unit實體。
        self:CreateUnit(self.initCreateCount)
    end

    -- 回傳unitPool(table)的最後一個元素，並從表格中移除該元素。
    -- ---@type Entity：明示該變數的類型。
    ---@type Entity
    local tempUnit = table.remove(self.unitPool,#self.unitPool)

    -- 將從Pool取得的unit實體父物件設定為收到的實體。
    tempUnit:AttachTo(parent)
    -- 因為預計使用該unit實體，所以將Enable設定更改為true並啟用。
    tempUnit.Enable = true

    -- 回傳實體元素。
    return tempUnit
}
```

## 歸還英雄
- ReturnUnit(unitEntity)函式會在英雄體力耗盡或角色結束時，不破壞英雄，而是重新回收到Pool時使用。
- 為了立即停止英雄實體的物理碰撞、移動運算，會設定內部功能。
- 透過**table.insert**將實體重新放入**unitPool**。
- 將實體本身以Enable = false停用，並將父物件更改為待機列實體(PoolParent)，處理為不顯示在畫面上。 

```lua
英雄歸還時的過程

Method:
[clientOnly]
OnDamage(integer damage)
{
    self.hp -= damage

    if self.hp <= 0 then
        _ObjectPoolLogic.ReturnUnit(self.Entity)
    end
}
```

```lua
ObjectPool的Return函式動作過程

Method:
[clientOnly]
ReturnUnit(Entity unitEntity)
{
    -- 停用登錄於歸還英雄的RigidbodyComponent功能。
    unitEntity.RigidbodyComponent.Enable = false
    -- 將收到的實體登錄為unitPool。
    table.insert(self.unitPool,unitEntity)
    -- 因實體使用已結束，停用Enable。
    unitEntity.Enable = false

    local unitPoolParentEntity = _EntityService:GetEntityByPath("/maps/MainGame/ObjectPool/UnitPool")

    -- 將歸還的英雄父實體重新移回PoolParent。
    unitEntity:AttachTo(unitPoolParentEntity)
}
```

- ObjectPool Logic的程式碼會如下撰寫。
- 該程式碼是在Plain Text環境下撰寫。

```lua
@Logic
script ObjectPoolLogic extends Logic

property integer initCreateCount = 5 -- 各Pool元素初始化時的生成次數。

property table unitPool = {} -- 管理英雄的Pool。

@ExecSpace("ClientOnly")
method void CreateUnit(integer createCount)
-- 依指定數量在unitPool中生成unit實體，並加入unitPool(Table)的函式。

-- 參數1 createCount：依收到的數量新生成Unit實體並登錄到Pool。

-- 記錄作為要生成unit原本來源的Model EntryID值。
local unitModelEntryID = "model://a8b9e5f1-0f95-4031-a2d9-47cda943aa9f"
-- Hierarch中用來儲存已停用Unit實體的父實體。 
local unitPoolParentEntity = _EntityService:GetEntityByPath("/maps/MainGame/ObjectPool/UnitPool")

-- 依傳入參數(createCount)數量執行反覆敘述。
for i = 1, createCount, 1 do
	-- 運用SpawnService生成(複製)Unit模型。
	local tempUnitEntity = _SpawnService:SpawnByModelId(unitModelEntryID,"Unit",Vector3.one * 1000, unitPoolParentEntity)
	-- 因為不是立即使用的實體，所以停用實體。
	tempUnitEntity.Enable = false
	-- 將生成的unit實體登錄到unitPool。
	table.insert(self.unitPool,tempUnitEntity)
end
end

@ExecSpace("ClientOnly")
method Entity GetUnit(Entity parent)

-- 取得Unit實體的函式。

-- 參數1 parent：將想接收的實體父物件設定為參數的實體。

-- 若unitPool中已無登錄的實體，
if #self.unitPool <= 0 then
	-- 生成新的unit實體。
	self:CreateUnit(self.initCreateCount)
end

-- 回傳unitPool(table)的最後一個元素，並從表格中移除該元素。
-- ---@type Entity：明示該變數的類型。
---@type Entity
local tempUnit = table.remove(self.unitPool,#self.unitPool)

-- 將從Pool取得的unit實體父物件設定為收到的實體。
tempUnit:AttachTo(parent)
-- 因為預計使用該unit實體，所以將Enable設定更改為true並啟用。
tempUnit.Enable = true

-- 回傳實體元素。
return tempUnit
end

@ExecSpace("ClientOnly")
method void ReturnUnit(Entity unitEntity)
-- 將啟用中的unit重新歸還至pool。

-- 參數1 unitEntity：接收想歸還的unitEntity。

unitEntity.RigidbodyComponent.Enable = false
-- 將收到的實體登錄為unitPool。
table.insert(self.unitPool,unitEntity)
-- 因實體使用已結束，停用Enable。
unitEntity.Enable = false

local unitPoolParentEntity = _EntityService:GetEntityByPath("/maps/MainGame/ObjectPool/UnitPool")

-- 將歸還的英雄父實體重新移回PoolParent。
unitEntity:AttachTo(unitPoolParentEntity)
end

@ExecSpace("ClientOnly")
method void ClearUnitPool()
self.unitPool = {}
end

end
```

## 最低製作標準
- 必須製作不破壞(Destroy)實體，而是以停用狀態儲存於表格中的歸還邏輯。
- 英雄請求時必須確認Pool(table)內部，並在不足時包含動態追加生成實體的例外處理。

<br>

## 應用與進階應用
- 各種類型Pool管理：不只英雄，也可以為投射體、打擊時顯示的傷害文字等頻繁生成/消滅的元素製作專用Pool管理。
- 前期只準備少量，並隨著波數進行、敵人變多，建立逐漸增加Pool儲存上限的系統。
