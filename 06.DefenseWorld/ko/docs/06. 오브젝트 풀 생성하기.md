## 영상 타입라인
- 강의 영상 내 아래의 타임라인에서 학습할 수 있습니다.
- 오브젝트 풀 생성하기: 02:02:50

<br>

## 학습 목표
- 엔티티 생성과 파괴가 반복될 때 발생하는 성능 저하의 원인을 파악하고, 오브젝트 풀링 기법의 필요성을 이해합니다.
- 여러 유닛을 미리 생성하여 대기 상태로 보관하는 Pool 자료구조를 직접 구현할 수 있습니다.
- 체력이 0이하의 유닛을 다시 오브젝트 풀로 반환하고, 필요할 때 초기화를 진행하여 다시 꺼내 사용하는 함수를 작성합니다.

<br>

## 해당 영상 시청 후 수행해 볼 내용
- ObjectPoolLogic 스크립트를 작성하고, 지정한 개수만큼 유닛이 비활성화 상태로 풀에 잘 생성되는지 확인합니다.
- 매번 유닛을 새로 생성하지 않고, GetUnit 함수를 통해 풀에서 꺼내 쓰도록 스폰 코드를 수정합니다.
- 유닛 체력이 0이 되었을 때 파괴(Destroy) 대신 ReturnUnit으로 풀에 반환하고, 이후 정상적으로 재활용되는지 확인합니다.

<br>

## 오브젝트 풀이란?
- 게임을 진행하는 데 있어 수많은 엔티티가 사용됩니다.
- 이러한 엔티티 중, 빈번하게 스폰되는 총알이나 발판 같은 요소는 일정 시간이 지나면 화면에서 사라져 소멸해야 합니다. 
- 하지만 생성(Spawn)과 소멸(Destroy) 작업은 메모리 할당과 해제를 동반하므로, 이 과정이 짧은 시간 동안 반복될 경우 컴퓨터 연산에 큰 부하(프레임 드랍)를 유발합니다.
- 하지만 미리 엔티티를 생성하고, 소멸시키는 대신 활성화만 해제한다면 컴퓨터의 부하를 줄일 수 있습니다.
- 스위치를 켜고 끄듯 상태만 전환하여 메모리를 재사용하기 때문입니다.
- 즉, 오브젝트 풀(Object Pool)은 미리 만들어 둔 엔티티들을 '수영장(Pool)'에 담아두고 필요할 때마다 꺼내 쓰며 반환하는 방식으로 불필요한 생성과 소멸을 최소화하는 핵심 최적화 기법입니다.

<br>

## Unit을 저장하는 오브젝트 풀 생성하기
- **Pool** 역할을 할 빈 테이블인 unitPool 프로퍼티를 선언합니다.
- CreateUnit(createCount) 함수를 통해 매개변수만큼의 유닛을 생성합니다.
- SpawnService를 활용해 원본 유닛 모델로부터 엔티티를 복제합니다.
- 바로 사용될 유닛이 아니므로 **Enable = false**로 설정해 비활성화한 뒤, **Pool** 테이블에 저장합니다.
- 다음 코드는 미리 유닛 엔티티를 미리 풀에 준비해 두는 과정의 예시를 작성한 코드입니다.

```lua
월드 실행 시 unitPool에 5개의 유닛을 미리 준비하는 과정

Property:
-- 유닛이 저장,관리될 Pool을 선언합니다.
[None]
table unitPool = {}
-- 비활성화 중인 유닛 엔티티가 하이어라키상에서 보관될 부모 엔티티 변수를 선언합니다.
[None]
Entity tempUnitParent

Method:
[clientOnly]
void OnBeginPlay()
{
    -- 월드 실행 시 5개의 유닛을 미리 생성합니다.
    CreateUnit(5)
}

[clientOnly]
void CreateUnit(integer createCount)
{
    local unitModelEntryID = "원본 모델 Entry ID"
    tempUnitParent = "비활성화 중인 엔티티가 하이어라키 상에서 저장될 부모 엔티티"

    -- 매개변수 createCount 횟수만큼 반복문을 수행합니다.
    for i = 1, createCount, 1 do
        -- SpawnService를 활용해 원본 모델로부터 새로운 엔티티를 생성합니다.
        local newUnit = _SpawnService:SpawnByModelId(
            unitModelEntryID, 
            "UnitName", 
            Vector.zero, 
            tempUnitParent
            )

        -- 생성된 유닛 엔티티를 비활성화해둡니다.
        newUnit.Enable = false
        -- 유닛이 저장되는 Pool 테이블에 새로 생성된 유닛 엔티티를 저장해둡니다.
        table.insert(self.unitPool,newUnit)
    end
}
```

## 오브젝트 풀로부터 유닛 가져오기
- GetUnit(parent) 함수는 유닛이 필요할 때 호출됩니다.
- 매개변수인 parent는 유닛 엔티티가 활성화되며 **parent**엔티티의 자식 엔티티로 등록됩니다.
- 먼저 unitPool에 사용할 수 있는 유닛이 있다면, 보관 중인 유닛 엔티티를 반환합니다.
- 만약 사용할 수 있는 유닛이 없다면, 새로 유닛을 생성해서 반환하도록 합니다.
- 유닛을 테이블에서 꺼낼 때는 **table.remove**기능을 활용합니다.
- 꺼낸 엔티티를 배치할 때는 parent로 이동(AttachTo)시킨 후, **Enable = true**로 활성화하여 게임에 투입시킵니다.

```lua
BaseComponent에서 유닛을 전달받는 과정

[clientOnly]
void SpawnUnit(string unitName)
{
    -- 오브젝트 풀로부터 유닛 엔티티를 전달받습니다.
    local unit = _ObjectPoolLogic:GetUnit(self.Entity)
    -- 유닛 엔티티의 위치를 스폰 지점의 위치로 설정합니다.
    unit.TransformComponent.Position = self.spawnLocation.TransformComponent.Position
    -- Unit의 UnitComponet에 접근하여 초기화를 진행시킵니다.
    unit.UnitComponent:Init(unitName,self.isUser)
}
```

```lua
ObjectPool Logic의 GetUnit 함수 동작과정

Method:
[clientOnly]
Entity GetUnit(Entity parent)
{
    -- unitPool에 더이상 등록된 엔티티가 없다면,
    if #self.unitPool <= 0 then
        -- 새로운 unit 엔티티를 생성합니다.
        self:CreateUnit(self.initCreateCount)
    end

    -- unitPool(table)의 가장 마지막 요소를 반환하며, 테이블에서 해당 요소를 제거합니다.
    -- ---@type Entity : 해당 변수의 타입을 명시합니다
    ---@type Entity
    local tempUnit = table.remove(self.unitPool,#self.unitPool)

    -- Pool로부터 가저온 unit 엔티티의 부모를 전달받은 엔티티로 설정합니다.
    tempUnit:AttachTo(parent)
    -- 해당 unit 엔티티를 사용할 예정이므로 Enable 설정을 true로 변경해 활성화 합니다.
    tempUnit.Enable = true

    -- 엔티티 요소를 반환해줍니다.
    return tempUnit
}
```

## 유닛 반환하기
- ReturnUnit(unitEntity) 함수는 체력이 다하거나 역할이 끝난 유닛을 파괴하지 않고 다시 풀로 회수할 때 사용합니다.
- 유닛 엔티티의 물리적 충돌, 이동 연산을 즉각적으로 중단하기 위해 내부 기능을 설정합니다.
- **table.insert**를 통해 다시 **unitPool**에 엔티티를 집어넣습니다.
- 엔티티 자체를 Enable = false로 비활성화하고, 부모를 대기열 엔티티(PoolParent)로 변경하여 화면에 보이지 않게 처리합니다. 

```lua
유닛시 반환되는 과정

Method:
[clientOnly]
OnDamage(integer damage)
{
    self.hp -= damage

    if self.hp <= 0 then
        _ObjectPoolLogic.ReturnUnit(self.Entity)
    end
}
```

```lua
ObjectPool의 Return함수 동작과정

Method:
[clientOnly]
ReturnUnit(Entity unitEntity)
{
    -- 반환하는 유닛에 등록된 RigidbodyComponent의 기능을 비활성화 합니다.
    unitEntity.RigidbodyComponent.Enable = false
    -- 전달받은 엔티티를 unitPool로 등록합니다.
    table.insert(self.unitPool,unitEntity)
    -- 엔티티의 활용이 끝났으므로 Enable을 비활성화합니다.
    unitEntity.Enable = false

    local unitPoolParentEntity = _EntityService:GetEntityByPath("/maps/MainGame/ObjectPool/UnitPool")

    -- 반환받는 유닛의 부모 엔티티를 다시 PoolParent로 이전합니다.
    unitEntity:AttachTo(unitPoolParentEntity)
}
```

- ObjectPool Logic의 코드는 다음과 같이 작성합니다.
- 해당 코드는 Plain Text 환경으로 작성되었습니다.

```lua
@Logic
script ObjectPoolLogic extends Logic

property integer initCreateCount = 5 -- 각 풀 요소별 초기화 시 생성 횟수입니다.

property table unitPool = {} -- 유닛을 관리할 풀 입니다.

@ExecSpace("ClientOnly")
method void CreateUnit(integer createCount)
-- 지정된 수량만큼 unitPool에 unit 엔티티를 생성하여 unitPool(Table)에 추가하는 함수입니다.

-- 매개변수 1 createCount : 전달받는 수량만큼 Unit엔티티를 새로 생성해 풀에 등록합니다.

-- 생성할 unit의 원본이 되는 Model의 EntryID 값을 기록합니다.
local unitModelEntryID = "model://a8b9e5f1-0f95-4031-a2d9-47cda943aa9f"
-- Hierarch에서 비활성화 된 Unit 엔티티들이 보관 될 부모 엔티티입니다. 
local unitPoolParentEntity = _EntityService:GetEntityByPath("/maps/MainGame/ObjectPool/UnitPool")

-- 전달매개 변수(createCount) 수량만큼 반복문을 수행합니다.
for i = 1, createCount, 1 do
	--SpawnService를 활용해 Unit 모델을 생성(복제)합니다.
	local tempUnitEntity = _SpawnService:SpawnByModelId(unitModelEntryID,"Unit",Vector3.one * 1000, unitPoolParentEntity)
	-- 바로 사용될 엔티티가 아니므로 엔티티를 비활성화 합니다.
	tempUnitEntity.Enable = false
	-- unitPool에 생성한 unit 엔티티를 등록해 둡니다.
	table.insert(self.unitPool,tempUnitEntity)
end
end

@ExecSpace("ClientOnly")
method Entity GetUnit(Entity parent)

-- Unit 엔티티를 가져오는 함수입니다.

-- 매개변수 1 parent : 전달받고자 하는 엔티티의 부모를 매개변수의 엔티티로 설정합니다.

-- unitPool에 더이상 등록된 엔티티가 없다면,
if #self.unitPool <= 0 then
	-- 새로운 unit 엔티티를 생성합니다.
	self:CreateUnit(self.initCreateCount)
end

-- unitPool(table)의 가장 마지막 요소를 반환하며, 테이블에서 해당 요소를 제거합니다.
-- ---@type Entity : 해당 변수의 타입을 명시합니다
---@type Entity
local tempUnit = table.remove(self.unitPool,#self.unitPool)

-- Pool로부터 가저온 unit 엔티티의 부모를 전달받은 엔티티로 설정합니다.
tempUnit:AttachTo(parent)
-- 해당 unit 엔티티를 사용할 예정이므로 Enable 설정을 true로 변경해 활성화 합니다.
tempUnit.Enable = true

-- 엔티티 요소를 반환해줍니다.
return tempUnit
end

@ExecSpace("ClientOnly")
method void ReturnUnit(Entity unitEntity)
-- 홣성화중인 unit을 다시 pool로 반환합니다.

-- 매개변수 1 unitEntity : 반환하고자 하는 unitEntity를 전달 받습니다.

unitEntity.RigidbodyComponent.Enable = false
-- 전달받은 엔티티를 unitPool로 등록합니다.
table.insert(self.unitPool,unitEntity)
-- 엔티티의 활용이 끝났으므로 Enable을 비활성화합니다.
unitEntity.Enable = false

local unitPoolParentEntity = _EntityService:GetEntityByPath("/maps/MainGame/ObjectPool/UnitPool")

-- 반환받는 유닛의 부모 엔티티를 다시 PoolParent로 이전합니다.
unitEntity:AttachTo(unitPoolParentEntity)
end

@ExecSpace("ClientOnly")
method void ClearUnitPool()
self.unitPool = {}
end

end
```

## 최소 구현 기준
- 엔티티를 파괴(Destroy)하지 않고 비활성화 상태로 테이블에 보관하는 반환 로직이 구현되어야 합니다.
- 유닛 요청 시 풀(table) 내부를 확인하고, 부족할 경우 동적으로 엔티티를 추가 생성하는 예외 처리가 포함되어야 합니다.

<br>

## 응용 및 확장 방향
- 다양한 종류의 풀 관리 : 유닛뿐만 아니라 발사체, 타격 시 발생하는 데미지 텍스트 등 자주 생성/소멸하는 요소에 전용 풀을 만들어 관리할 수 있습니다.
- 초반에는 적은 수량만 준비하고, 웨이브가 진행되어 적이 많아질수록 풀의 보관 한도를 늘려가는 시스템을 구축해 봅니다.
