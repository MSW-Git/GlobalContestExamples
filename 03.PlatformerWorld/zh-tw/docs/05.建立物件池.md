## 學習目標
- 掌握當實體(物件)生成與銷毀反覆發生時造成效能下降的原因，並理解為了解決此問題而需要物件池。
- 可在遊戲開始時預先生成所需地圖區塊或障礙物實體，並親自製作儲存在待機狀態中的池資料結構。
- 撰寫將超出畫面外的實體不刪除而改為停用後回收到池中，並在需要時重設位置再取出使用的重複利用方法。
<br>

## 觀看該影片後可嘗試執行的內容
- 使用邏輯腳本，在遊戲初始化階段預先生成指定數量的圖塊集實體後，以停用狀態儲存起來。
- 實際測試碰到畫面左端DeadZone的圖塊是否不是被刪除，而是在屬性被初始化後再次回到物件池待機。
- 在程序化地圖生成時，不是每次都建立新的實體，而是確認會不會從物件池取出待機中的實體，並正常接續在前一個圖塊的終點座標。
<br>

## 什麼是物件池?
- 在遊戲進行時會使用大量實體。
- 其中，像子彈或平台這種會頻繁生成的要素，過一段時間後就必須從畫面上消失並被銷毀。 
- 但是生成(Spawn)與銷毀(Destroy)作業會伴隨記憶體配置與釋放，因此如果這個過程在短時間內反覆進行，就會對電腦運算造成很大負擔(掉幀)。
- 但若事先建立實體，並不是消滅而只是停用，就能減少電腦負擔。
- 因為它是像開關一樣，只切換狀態並重複利用記憶體。
- 也就是說，**物件池(Object Pool)**是一種核心最佳化，它會把預先建立的實體放進「水池(Pool)」中，需要時再取出使用並回收，藉此將不必要的生成與銷毀降到最低。
<br>

## 製作物件池
- 範例世界的物件池，是像GameLogic或DataSetLogic一樣，製作成可在任何地方以全域方式存取，並輕鬆借出與回收實體的集中管理(管理者)結構。
- 在Workspace中建立新的邏輯，並命名為ObjectPoolLogic。

## 撰寫ObjectPoolLogic腳本
- 必須如下撰寫程式碼。
- 該程式碼是在Plain Text環境下撰寫。

```lua
@Logic
script ObjectPoolLogic extends Logic

property number discript = 0 -- 這是高效率管理頻繁發生建立與銷毀物件的邏輯。

property table tilePool = {} -- 這是用來扮演管理圖塊集物件的池角色的表格。

property table itemPool = {} -- 這是用來扮演管理道具物件的池角色的表格。

property Entity ItemPoolParent = "9e9e98bd-4f7b-46ed-9a93-f0e7d74fac1c"

property table itemDataSetIDTable = {["Coin"] = 1 ,["Health"] = 2 ,["Booster"] = 3} -- key：道具名稱，value：用來儲存資料集Index編號的表格。

@ExecSpace("ClientOnly")
method void ReturnTile(Entity entity)
-- 這是將圖塊物件回收至物件池的方法。

-- 參數1 entity：傳入欲回收(停用)的物件。
-- 參數2 tileNumber：傳入圖塊編號。

-- 取出圖塊集實體的編號。(為了依照表格內編號管理圖塊集物件。)
local tileNumber = self:GetTileNumber(entity)

-- 檢查圖塊編號對應的池(表格)是否有效。
if isvalid(self.tilePool[tileNumber]) == false or self.tilePool[tileNumber] == nil then
	-- 若表格不存在，則新建新的表格空間。
	self.tilePool[tileNumber] = {}
end

-- 將目標實體(物件)儲存至目標表格。
table.insert(self.tilePool[tileNumber],entity)
-- 停用實體(物件)。
entity.Enable = false
end

@ExecSpace("ClientOnly")
method Entity GetTile(number tileNumber)
-- 從圖塊池取得指定編號圖塊實體的方法。

-- 參數1 number tileNumber：傳入特定圖塊集編號。

-- 使用math.floor方法去除tileNumber的小數部分。 ex) 4.0 => 4
tileNumber = math.floor(tileNumber)

-- 進行目標池(表格)有效性檢查。

-- 若不存在管理傳入tileNumber圖塊物件的池(表格)
if isvalid(self.tilePool[tileNumber]) == false or self.tilePool[tileNumber] == nil then
	-- 則建立新的表格空間。
	self.tilePool[tileNumber] = {}
end

-- /分支1/ 若沒有則新建後回收。

-- 若目標池內已無物件(將從模型(Prefab)重新建立物件。)
if #self.tilePool[tileNumber] <= 0 then
	
	-- 確認表格集中儲存的EntryID。
	local entryID = _DataSetLogic.tileSetInfoTable[tileNumber].EntryID
	-- 以預先儲存的(Prefab)名稱類型儲存名稱。
	local name = "Model_TileSet0"..tileNumber
	
	-- 在臨時位置生成目標模型(Prefab)物件。
	local tempTile = _SpawnService:SpawnByModelId(entryID,name,Vector3.up*100,_EntityService:GetEntity("d24b5917-1821-4743-ae07-77cc9bfc2d0a"))
	
	-- 回收該物件。
	return tempTile
end

-- /分支2/ 若有則取出最後一個元素。

-- 確認目前目標表格數量。
local tableCount = #self.tilePool[tileNumber]

-- 取出目標表格最後一個元素，並將該實體從表格移除。
local tempTile = table.remove(self.tilePool[tileNumber],tableCount)

-- 啟用選取的物件。
tempTile.Enable = true

-- 回收物件。
return tempTile


end

@ExecSpace("ClientOnly")
method Entity GetItem(string itemName)
-- 從物件池取得道具物件的方法。

-- 參數1 string itemName：傳入道具名稱。

-- 從道具池取得存放目標道具的表格。
local targetTable = self.itemPool[itemName]

-- 當表格內元素為空時
if #targetTable == 0 then
	-- 依照Config設定的生成數量追加生成目標道具。
	self:CreateItem(itemName,_Config.itemPoolInitCount)
end


-- 從欲取得的表格中載入實體。(表格最後一個元素)
---@type Entity
local targetEntity = targetTable[#targetTable]

-- 因已儲存實體，因此移除表格最後一個元素。
table.remove(targetTable,#targetTable)

-- 啟用實體(物件)。
targetEntity.Enable = true

-- 回收已儲存的實體。
return targetEntity
end

@ExecSpace("ClientOnly")
method void ReturnItem(Entity entity)
-- 將道具物件再次回收至物件池的方法。

-- 參數1 Entity entity：傳入欲回收的道具物件實體。

-- 確認回收道具的名稱。
local itemName = entity.Item.name
-- 將實體放入目標表格。
table.insert(self.itemPool[itemName],entity)

-- 從圖塊集原本的Parent(為配置圖塊集道具而預先登錄的物件) 
-- 再將Parent移回ItemPool。
entity:AttachTo(self.ItemPoolParent)
-- 停用實體(物件)。
entity.Enable = false
end

@ExecSpace("ClientOnly")
method void CreateItem(string itemName, number createCount)
-- 從模型(Prefab)重新生成道具物件並放入目標池的方法。

-- 參數1 string itemName：傳入欲生成的道具名稱。
-- 參數2 number createCount：生成數量，決定要放入多少物件到物件池。

-- 宣告臨時表格。
local tempTable

-- 設定資料集要參照的Id編號。
local dataSetID = self.itemDataSetIDTable[itemName]

-- 載入資料集中目標道具模型的EntryID值。
local entryID = _DataSetLogic.itemInfoTable[dataSetID].EntryID
-- 載入資料集中目標道具模型的Name值。
local name = _DataSetLogic.itemInfoTable[dataSetID].Name
-- 載入資料集中目標道具模型的Value值。
local value = _DataSetLogic.itemInfoTable[dataSetID].Value

-- 進行目標表格有效性檢查。

-- /分支1/ 若目標道具池內沒有目標池(表格)
if isvalid(self.itemPool[name]) == false or self.itemPool[name] == nil then
	-- 建立新的臨時表格。
	tempTable = {}
	-- 將道具池中的內部池(表格)設為臨時表格。
	self.itemPool[name] = tempTable
	
-- /分支2/ 若目標道具池內已存在目標池
else
	-- 將臨時表格(池)設為既有使用中的表格。
	tempTable = self.itemPool[name]
end

-- 執行參數2 createCount次迴圈。
for i = 1 , createCount, 1 do 
	-- 使用SpawnService建立物件。
	local entity = _SpawnService:SpawnByModelId(entryID,name,Vector3.up * 100, self.ItemPoolParent)
	
	-- 進行建立物件的設定作業。
	
	-- 設定建立物件的道具固有數值。
	entity.Item.value = value
	-- 設定建立物件的道具name變數。
	entity.Item.name = name
	
	-- 將建立的實體插入應存放的表格(池)。
	table.insert(tempTable,entity)
	
	-- 停用建立的實體物件。
	entity.Enable = false
end
end

@ExecSpace("ClientOnly")
method void InitItemPool()
-- 初始化道具池的方法。

-- 從DataSetLogic載入存放道具資料集的表格。
local itemDataTable = _DataSetLogic.itemInfoTable

-- 依照Config設定的生成數量生成Coin道具。
self:CreateItem("Coin",_Config.itemPoolInitCount)
-- 依照Config設定的生成數量生成Health道具。
self:CreateItem("Health",_Config.itemPoolInitCount)
-- 依照Config設定的生成數量生成Booster道具。
self:CreateItem("Booster",_Config.itemPoolInitCount)
end

@ExecSpace("ClientOnly")
method void Init()
-- 執行ObjectPool Logic初始化的方法。

-- 進行道具池初始化。
self:InitItemPool()
end

@ExecSpace("ClientOnly")
method number GetTileNumber(Entity entity)
-- 取出圖塊編號的方法。

-- 參數1 Entity entity：傳入目標實體。

-- 取出實體名稱。
local tileSetName = entity.Name
-- 取出名稱最後字串。('Model_TileSet02' 字串中取出第14、15個字元 > 02)
local numberStr = string.sub(tileSetName,14,15)
-- 將字串切換為數值後回收。
return tonumber(numberStr)
end

end
```

- ObjectPoolLogic會管理週期性生成與銷毀的地板圖塊集、各種道具元素。
- 已撰寫的GetTile方法會執行從圖塊池取出待機中的地板圖塊功能，並在ScrollingController元件需要生成新地圖碎片時被呼叫。
- ReturnTile方法會在超出畫面的地板圖塊與DeadZone碰撞時，由TileDeadZone腳本使用，將該圖塊回收(停用)至池中，而非銷毀。
<br>

## 最低製作標準
- 當地圖捲動進行時，圖塊集實體不會反覆生成與銷毀(Destroy)，而是透過物件池系統正常停用與重新啟用並循環使用。
- 所有圖塊集皆以從物件池生成或回收可使用實體的類型製作。
<br>

## 應用與進階應用
- 修改程式碼，讓其符合物件池**預先生成**後使用的原則。
- 依據修改後的程式碼，確認不只是地板圖塊，遊戲中頻繁出現的障礙物或道具元素，也能透過物件池正常重複使用。
- 並非一開始無條件大量生成，而是在物件池內待機實體不足時，才動態擴大池大小(追加生成)，製作更佳記憶體最佳化的擴充邏輯。
