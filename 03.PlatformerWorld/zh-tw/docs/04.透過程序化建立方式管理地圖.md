## 理解程序化地圖生成的概念
- 所謂程序化地圖生成，是指與其從頭到尾手動配置地形，不如依照既定規則與演算法，在遊戲進行時即時生成地圖的系統。
- 這是在必須不斷奔跑的無限跑酷類型中，用來無限制延長地圖長度，並在每次遊玩時建立多樣化地形樣式所需的核心基礎技術。
<br>

### 克服無限地圖的限制
- 在跑酷遊戲中，若要把玩家奔跑的地圖從頭到尾都在編輯器中事先做得很長，不只工作量龐大，在系統記憶體層面也有很大限制。
- 為了解決這個問題，便導入一種會依照遊戲進行狀況即時建立新地圖碎片的「程序化建立」。
- 套用這種功能後，就像在奔跑列車前方持續鋪設鐵軌一樣，既能無限延長地圖，也能有效率地管理系統資源。
<br>

### 以圖塊集(區塊)為單位的分割管理與隨機性
- 即時生成地圖時，並不是隨機一格一格像素或圖塊地打出來，而是先製作並管理多種固定長度的地圖碎片(區塊)樣式。
- 腳本會從這些預先做好的碎片中，依照規則隨機選擇一個，再像樂高積木一樣接到前一塊的尾端。
- 透過這種方式，不但能維持地圖結構的穩定性，也能讓玩家每次遊玩時遇到不同類型的地形，進而大幅提升遊戲重玩性。
<br>

## 製作區塊地圖
- 所謂區塊，是指在程序化地圖建立系統中，用來銜接地形的預先製作固定大小地圖碎片。
<br>

### 建立地板圖塊實體
<p align = "Center">
<img src ="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Running/MSW-100_Running_4_001.png" alt="MSW-100_Running_4_001.png">
</p>

- 為了建立一個單位的區塊，先建立一個作為圖塊父層的空白實體。
- 此時，為了讓在編輯器中配置圖塊時作業更順利，請將父實體座標設為原點(0,0,0)。
- 登錄多個子實體，並附加SpriteRendererComponent。
- 設定SpriteRendererComponent的RUID值以登錄外型。
- 除了父實體外，對各地板實體登錄PhysicsRigidbody、PhysicsCollider元件，並設定成可與角色互動。
- 透過PhysicsCollider元件中的collider edit按鈕，修改碰撞器的位置與尺寸。

### 在DataSet中登錄各地板圖塊資料
<p align = "Center">
<img src ="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Running/MSW-100_Running_4_006.png" alt="MSW-100_Running_4_006.png">
</p>

1. 這是實際儲存的DataSet(TileSetInfo)結構的一部分。
2. 這是顯示DataSetLogic將以何種方式儲存到表格中的表。

- 範例世界的地板圖塊製作成1樓與2樓兩種。因此tileFloorInfoTable也分成[1]與[2]兩個陣列，分別管理與存取。

```lua
DataSetLogic的tileFloorInfoTable儲存程式碼

table tilesFloorInfoTable = {[1]={}, [2]={}}

void InitTileSetInfoTable()
{
    -- 用來儲存圖塊物件相關資料集的方法。

    -- 用來在本地端存取儲存在工作空間資料集名稱的變數。
    local dataSetName = "TileSetInfo"

    -- 目標資料集的Row數。
    local rowCount = self:GetDataSetRowCount(dataSetName)

    -- 儲存圖塊集種類數。
    self.totalTileSetCount = rowCount

    -- 用來儲存各列資料的變數。
    local rowData

    -- 從1開始依資料集Row數進行巡覽。
    for i = 1 , rowCount , 1 do
        rowData = 
        {
            -- 圖塊集物件第一個圖塊的樓層。
            FirstFloor = tonumber(_DataService:GetCell(dataSetName,i,"FirstFloor")),
            -- 圖塊集物件最後一個圖塊的樓層。
            LastFloor = tonumber(_DataService:GetCell(dataSetName,i,"LastFloor")),
            -- 用來建立圖塊集物件的原始實體模型(Prefab)Id。
            EntryID = _DataService:GetCell(dataSetName,i,"EntryID")
        }

        -- 將以rowData儲存的資料存入表格。
        self.tileSetInfoTable[i] = rowData
        
        -- 將剛登錄的圖塊集樓層存入變數。
        local firstTileFloor = self.tileSetInfoTable[i].FirstFloor
        
        -- /分支1/ 若第一個圖塊樓層為1樓
        if firstTileFloor == 1 then
            -- 存入1樓表格清單。
            table.insert(self.tilesFloorInfoTable[1],i)
        -- /分支2/ 若第一個圖塊樓層不是1樓
        else
            -- 存入2樓表格清單。
            table.insert(self.tilesFloorInfoTable[2],i)
        end
    end
}

number GetDataSetRowCount(string Name)
{
    -- 回傳目標資料集的Row數。

    -- 參數1 string Name：傳入目標資料集名稱。

    -- 回傳確認過的資料集Row數。
    return _DataService:GetRowCount(Name)
}
```
<br>

### 使用登錄在DataSet中的各地板圖塊資料
- 儲存好的tilesFloorInfoTable中，各樓層的表格可分類如下。
  - tilesFloorInfoTable[1]：存有從1樓開始的地板圖塊集編號的表格
  - tilesFloorInfoTable[2]：存有從2樓開始的地板圖塊集編號的表格
- 確認最後建立的地板圖塊終點樓層，並從各樓層表格中抽出隨機圖塊編號。
- 登錄最後圖塊樓層的方法，是更新最後建立的圖塊集的lastFloor值。

```lua
ScrollingController中建立圖塊方法的一部分

number lastTileFloor

void SpawnTile(number tileSetNumber)
{
    -- 從物件池取得「參數」編號的圖塊物件。
    local spawnedTile = _ObjectPoolLogic:GetTile(tileSetNumber)

    -- 記錄從物件池生成之圖塊集的結束點樓層。
    self.lastTileFloor = _DataSetLogic.tileSetInfoTable[tileSetNumber].LastFloor
}
```

### 多個區塊地圖的移動原理
<p align = "Center">
<img src ="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Running/MSW-100_Running_4_007.gif" alt="MSW-100_Running_4_007.gif">
</p>

- 在世界中，實際負責移動的是Scrolling的子實體TileParent。
- 並不是每個區塊地圖圖塊集實體各自執行移動，而是把它們登錄為實際執行移動的TileParent的子實體，使其自動跟著移動。
- 也就是說，TileParent在正式開始遊戲時會持續朝-x軸(由右往左)移動，而若登錄為TileParent實體的子實體，子實體也會自動同樣移動。
<br>

### 登錄為TileParent實體的子實體
<p align = "Center">
<img src ="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Running/MSW-100_Running_4_008.png" alt="MSW-100_Running_4_008.png">
</p>

- 可透過EntityService取得Hierarchy中的實體。
- 若要取得目標實體的Entity ID，可在Hierarchy中對該實體按右鍵後，透過Copy Entity ID複製ID值。
- SpawnService的SpawnByModelId方法可在第4個參數(Parameter)指定建立物件的父層(Parent)實體。
- 從先前製作的地板圖塊集模型生成新實體時，設定其Parent。
<br>

```lua
使用SpawnService的SpawnByModelId方法範例

void SpawnTile()
{
    // 從DataSetLogic取得2號區塊地圖圖塊的EntryID
    local entryID = _DataSetLogic.tileSetInfoTable[2].EntryID

    // 將要生成的新實體名稱
    local entityName = "TempEntity"

    // 將要生成的座標值
    local spawnPosition = Vector3(50,0,0)

    // 新生成實體的父層實體
    local tileParentEntity = _EntityService:GetEntity("d24b5917-1821-4743-ae07-77cc9bfc2d0a")

    _SpawnService:SpawnByModelId(entryID,entityName,spawnPosition,tileParentEntity)
}
```

### 製作與Tile互動的DeadZone
<p align = "Center">
<img src ="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Running/MSW-100_Running_4_010.png" alt="MSW-100_Running_4_010.png">
</p>

- 為了不讓玩家看見地板圖塊被移除的狀況，在離攝影機區域很遠的地方建立新實體。
<br>

<p align = "Center">
<img src ="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Running/MSW-100_Running_4_011.png" alt="MSW-100_Running_4_011.png">
</p>

1. 在作為TileDeadZone角色的實體上建立TriggerComponent。
2. 透過已附加TriggerComponent的Collider的Edit按鈕，設定碰撞偵測範圍。
<br>

<p align = "Center">
<img src ="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Running/MSW-100_Running_4_012.png" alt="MSW-100_Running_4_012.png">
</p>

1. 建立TileDeadZone元件腳本並登錄至TileDeadZone。
2. 以TileDeadZone的Plain Text登錄程式碼內容。
<br>

```lua
@Component
script TileDeadZone extends Component

property number discript = 0 -- 這是負責圖塊物件銷毀(停用)的元件。

property PhysicsColliderComponent collider = nil

@ExecSpace("ClientOnly")
method void ConnectRefs()
-- 連接內部所需成員參照。

-- 連接用來執行碰撞偵測的PhysicsCollider元件。
self.collider = self.Entity.PhysicsColliderComponent
end

@ExecSpace("ClientOnly")
method void Init()
-- 進行TileDeadZone元件初始化的方法。

-- 執行以變數宣告的參照連接。
self:ConnectRefs()
end

@ExecSpace("ClientOnly")
method void OnBeginPlay()
-- 這是在世界執行時呼叫的方法。

-- 進行該元件初始化。
self:Init()
end

@EventSender("Self")
handler HandleTriggerEnterEvent(TriggerEnterEvent event)
-- 這是在偵測到觸發碰撞時發生的事件。

-- 儲存觸發碰撞的實體。
local TriggerBodyEntity = event.TriggerBodyEntity
-- 確認碰撞觸發的Collision群組的id值。
local TriggerGroup = tostring(TriggerBodyEntity.TriggerComponent.CollisionGroup.Id)

-- 若將上述群組id值作為key代入Config中登錄的表格時，回傳的字串為「Ground」
-- 也就是說，若以觸發偵測到的碰撞體是Ground
if _Config.triggerGroup[TriggerGroup] == "Ground" then
	
	-- 就執行回收圖塊集物件。
	_ObjectPoolLogic:ReturnTile(TriggerBodyEntity.Parent)
	
	-- 要求捲動控制器生成接續在最後圖塊後面的隨機圖塊。
	_GameLogic.scrollingController:SpawnRandomTile()
end
end

end
```

## 最低製作標準
- 製作成起始樓層與結束樓層配對資料能正確運作，且圖塊之間不會斷裂。
- 製作成依照捲動畫面移動速度，新的地圖碎片會及時生成，不會讓角色因缺少平台而掉出地圖外。
<br>

## 應用與進階應用
- 可登錄多種不同地板圖塊模型，藉由擴充或更改種類，調整隨機生成權重，使高難度地圖碎片更常出現。
