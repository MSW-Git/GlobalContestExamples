## Understanding the Concepts of Procedural Map Generation
- Procedural map generation refers to a system that creates terrain in real time from beginning to end according to set rules and algorithms instead of placing them by hand.
- This is a core piece of technology that is needed to extend the map length indefinitely and have different terrain patterns each time for the infinite running game genre.
<br>

### Overcoming the Limits of an Infinite Map
- Not only would creating a map in the editor that the player will be running across for a running platformer game mean an overwhelming workload, it would also place a massive burden on the system's memory.
- To resolve this issue, the 'procedural generation' technique is implemented so that new map pieces can be created in real time as the game play continues.
- Using this technique is like placing tracks in front of a train that's currently running, which functionally extends the map an infinite amount while also making management efficient.
<br>

### Management of Tile Set (Chunk) Units and Randomness
- Each pixel and tile isn't being randomly created for the map in real time. In actuality, map fragments in set lengths (chunks) will be created in advance and managed in various patterns.
- The script chooses one of the already created chunks at random in accordance with the rules and attaches it to the end of the previous chunk like one would a lego block.
- This allows for the map to be structurally stable while also giving the player a unique terrain type to adapt to each time they start a run, therefore increasing replayability.
<br>

## Creating Map Chunks
- Chunks refer to a map fragment of a set size that was created in advance for the procedural generation system to use when connecting terrain.

### Registering Each Tile Data to the DataSet
<p align = "Center">
<img src ="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Running/MSW-100_Running_4_006.png" alt="MSW-100_Running_4_006.png">
</p>

1. This is a portion of the actually saved DataSet(TileSetInfo) structure.
2. This graph displays how it's saved to the table from DataSetLogic.

- The sample world's floor tiles are made up as Fl. 1 and Fl. 2. So tileFloorInfoTable is also separated in to 2 arrays, [1] and [2], so they can be independently managed and accessed.

```lua
-- DataSetLogic's tileFloorInfoTable Save Code

table tilesFloorInfoTable = {[1]={}, [2]={}}

void InitTileSetInfoTable()
{
    -- This method is needed to save the data set that's related to tile object.

    -- This variable is needed to access the name of the data set that is saved in world space as local.
    local dataSetName = "TileSetInfo"

    -- The number of Rows of the target data set.
    local rowCount = self:GetDataSetRowCount(dataSetName)

    -- Saves the number of tile set types.
    self.totalTileSetCount = rowCount

    -- A variable to hold the data for each line.
    local rowData

    -- Starts iterations a number of times equal to the number of data set Rows starting from 1.
    for i = 1 , rowCount , 1 do
        rowData = 
        {
            -- The number of floors for the first tile of the tile set object.
            FirstFloor = tonumber(_DataService:GetCell(dataSetName,i,"FirstFloor")),
            -- The number of floors for the last tile of the tile set object.
            LastFloor = tonumber(_DataService:GetCell(dataSetName,i,"LastFloor")),
            -- The original entity model (prefab) Id needed to create a tile set object.
            EntryID = _DataService:GetCell(dataSetName,i,"EntryID")
        }

        -- Saves the data stored as rowData to a table.
        self.tileSetInfoTable[i] = rowData
        
        -- Saves the number of floors currently registered in the tile set as a variable.
        local firstTileFloor = self.tileSetInfoTable[i].FirstFloor
        
        -- /Branch 1/ If the first tile floor number is Fl. 1,
        if firstTileFloor == 1 then
            -- saves to the Fl. 1 table list.
            table.insert(self.tilesFloorInfoTable[1],i)
        -- /Branch 2/ If the first tile floor number isn't Fl. 1,
        else
            -- saves to the Fl. 2 table list.
            table.insert(self.tilesFloorInfoTable[2],i)
        end
    end
}

number GetDataSetRowCount(string Name)
{
    -- Returns the number of Rows of the target data set.

    -- Parameter 1 string Name: Receives the name of the target data set.

    -- Returns the number of Rows of the verified data set.
    return _DataService:GetRowCount(Name)
}
```
<br>

### Utilizing Each Floor Tile Data Registered to DataSet
- The tilesFloorInfoTable table for each floor that was saved can be categorized as follows.
  - tilesFloorInfoTable[1]: The table containing the tile set numbers that start from Fl. 1
  - tilesFloorInfoTable[2]: The table containing the tile set numbers that start from Fl. 2
- Verifies the floor number of the end point for the floor tile that was generated last and extracts a random tile number from within the table for each floor.
- Updates the lastFloor value of the tile set that spawns last as a method to register the last tile's floor number.

```lua
-- Part of the method that generates the ScrollingController's tile

number lastTileFloor

void SpawnTile(number tileSetNumber)
{
    -- Receives the 'parameter' tile object from the object pool.
    local spawnedTile = _ObjectPoolLogic:GetTile(tileSetNumber)

    -- Records the floor of the end point for the tile set that was spawned from the object pool.
    self.lastTileFloor = _DataSetLogic.tileSetInfoTable[tileSetNumber].LastFloor
}
```

<p align = "Center">
<img src ="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Running/MSW-100_Running_4_012.png" alt="MSW-100_Running_4_012.png">

1. Create a TileDeadZone component script and register it to TileDeadZone.
2. Register the code content using the TileDeadZone's Plain Text.
<br>

```lua
@Component
script TileDeadZone extends Component

property number discript = 0 -- The component that manages the destruction (deactivation) of tile objects.

property PhysicsColliderComponent collider = nil

@ExecSpace("ClientOnly")
method void ConnectRefs()
-- Links the references of the internally required members.

-- Links the PhysicsCollider component needed to detect colliding bodies.
self.collider = self.Entity.PhysicsColliderComponent
end

@ExecSpace("ClientOnly")
method void Init()
-- This method resets the TileDeadZone component.

-- Executes a reference link that was declared as a variable.
self:ConnectRefs()
end

@ExecSpace("ClientOnly")
method void OnBeginPlay()
-- This method is called when the world is launched.

-- Resets the target component.
self:Init()
end

@EventSender("Self")
handler HandleTriggerEnterEvent(TriggerEnterEvent event)
-- This event is triggered when a trigger collision is detected.

-- Saves the entity of the trigger collision.
local TriggerBodyEntity = event.TriggerBodyEntity
-- Verifies the Collision group's id value of the collided trigger.
local TriggerGroup = tostring(TriggerBodyEntity.TriggerComponent.CollisionGroup.Id)

-- If the returned string is 'Ground' upon inserting the above group id value as the key value in the table register in Config,
-- in other words, if the colliding body that's detected as a trigger is Ground,
if _Config.triggerGroup[TriggerGroup] == "Ground" then
	
	-- executes a tile set object return.
	_ObjectPoolLogic:ReturnTile(TriggerBodyEntity.Parent)
	
	-- Calls the scrolling controller for a random tile creation that will connect to the last tile.
	_GameLogic.scrollingController:SpawnRandomTile()
end
end

end
```

## Minimum Implementation Standards
- The starting floor number and end floor number matching data acts precisely and without any gaps between tiles.
- New map chunks are generated at the right time matching the scroll speed so that the character doesn't fall off the map due to a missing platform.
<br>

## Usage and Extension Direction
- Register various floor tile models (Model) to expand or change the types in order to adjust the random generation weight so that higher difficulty map chunks appear more frequently.
