- The components required for the obstacle entity are SpriteRendererComponent and TriggerComponent.
- The SpriteComponent is intended to represent the appearance of the obstacle.
- The TriggerComponent is intended to detect collisions with the character but not to cause an actual physical collision, such as the character being blocked and pushed.

### Randomly Placing Obstacles
- If the prepared obstacles are placed on every tile, the game could become monotonous, so utilize the Random feature to make the obstacles appear in an irregular pattern.
- The ability to randomly place pre-placed obstacles occurs when the tileset is activated from a TileSet Component script registered to the floor tileset.
- The random obstacle placement feature can be handled with the following code.

```lua
SpawnObstacle method in the TileSet script

-- The parent entity of the obstacle entities.
Entity obstacleParent

void SpawnObstacle()
{
    -- Check the number of pre-installed obstacle objects in the tileset.
    -- Determine the number of children (obstacle entities) of the parent entity that hold the obstacles.
    local spawnLocationCount = self.obstacleParent.Children.Count

    -- Iterate through the child objects of the obstacleParent object
    for index , child in pairs(self.obstacleParent.Children) do
        
        -- and generate a random number from 0 to 1 (implementation intent: 50% chance of placing obstacle, O if 0 and X if 1).
        local randomNumber = math.random(0,1)
        
        -- /branch 1/ If the number is zero
        if randomNumber == 0 then
            -- Enable the obstacle object.
            child.Enable = true
            -- Overwrite with a resource image that matches the stage number.
            child.SpriteRendererComponent.SpriteRUID = _DataSetLogic.stageRenderInfoTable[_GameLogic.currentStage].ObstacleRUID
            
        
        -- /branch 2/ If the number is not zero,
        else
            -- Disable the obstacle object.
            child.Enable = false
        end	
    end
}

```

## Obstacle Hit Detection
<p align = "Center">
<img src = "../../_images/MSW-100_Running_9_004.png" alt="MSW-100_Running_8_005.png">
</p>

- If the character's TriggerComponent and the obstacle's TriggerComponent are properly registered, they can utilize each other's Trigger events.
- Utilize the HandleTriggerEnterEvent event method within the CustomPlayer script created to directly control the character's functionality and action.
- If the contents of the CustomPlayer code is needed, the CustomPlayer script is attached in the '6. Implementing Player Characters' section.
- Collision handling can be handled with the following code.

```lua
-- Collision Handling with event handlers in CustomPlayer

HandleTriggerEnterEvent(TriggerEnterEvent event)
{
    -- Save the entity information of the collided target.
    local TriggerBodyEntity = event.TriggerBodyEntity

    -- Extracts the collision group ID number set in the target entity's CollisionGroup.
    local TriggerGroup = tostring(TriggerBodyEntity.TriggerComponent.CollisionGroup.Id)

    -- If the group name of the collision object is the same as "Obstacle"
    if _Config.triggerGroup[TriggerGroup] == "Obstacle" then
        -- Perform collision detection processing.
        self:ContactObstacle()
    end
}

void ContactObstacle()
{
    -- Tells GameLogic to reduce HP by the obstacle damage value set in Config.
    _GameLogic:AddHP(_Config.obstacleDamage)
}

```

## Add Character Invincibility
<p align = "Center">
<img src = "../../_images/MSW-100_Running_9_005.gif" alt="MSW-100_Running_8_005.gif">
</p>

- If an obstacle with a HandleTriggerStayEvent event method that doesn't have a fixed invincibility time is created, the character may end up taking damage every frame, which can quickly bring them to zero health.
- By blocking additional damage for a short period of time immediately after hitting an obstacle, it gives the player more time to recognize the situation and readjust their stance.
- The ability to ignore hits for a period of time can be handled with the following code.

```lua
-- Utilizing invincibleTimer of CustomPlayer

-- Declare a temporary invincibility timer variable.
number invincibleTimer
-- Declare a variable that indicates the hit state.
boolean isHit

void ContactObstacle()
{
    -- If the value of the temporary invincibility timer variable is greater than 0 (the temporary invincibility timer is running)
    if self.invincibleTimer > 0 then
    -- Terminates the method without performing any hit detection due to obstacles.
        return
    end

    -- If the above conditions have not been executed (the temporary invincibility timer is not running)

    -- Decreases HP.
    _GameLogic:AddHP(_Config.obstacleDamage)
    
    -- Toggles the hit state to true.
    self.isHit = true;

    -- Reduce the alpha value of the character's appearance by half to make it see-through, so the player knows they are in invincible state.
    self.Entity.AvatarRendererComponent:SetAlpha(0.5)

    -- Updates the invincibility time value to set to allow the temporary invincibility timer to perform an action.
    self.invincibleTimer = _Config.invincibleTime
}

void OnUpdate(number delta)
{
    -- Utilizes the isHit value to prevent the code below from being executed when not in an isHit situation.
    if self.isHit == true then

        -- If the value of the temporary invincibility timer is greater than zero,
        if self.invincibleTimer > 0 then
        -- Decreases the value of the timer by the delta value. 
            self.invincibleTimer -= delta
        
        -- If the temporary invincibility timer has no duration left,
        else
        -- Increases the alpha value of the character's appearance to its original value (1) to make it opaque, so the player knows that invincibility has ended.
            self.Entity.AvatarRendererComponent:SetAlpha(1);
        end
    end
}

```

## Minimum Implementation Standards
- The obstacle entity should be moved the same as the floor tiles.
- Collisions between player characters and obstacles should result in a hit detection, and the obstacle should not push the character backward.
- Temporary invincibility must be activated when hit by an obstacle and must not take damage while the timer is running.
<br>

## Usage and Extension Direction
- Can add static-looking obstacles as well as active obstacles with dynamic animations that rise up and down in place.
- As the game progresses (over time), the difficulty of the game can be adjusted by making obstacles more or less likely to spawn.
