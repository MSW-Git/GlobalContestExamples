## 영상 타임라인
- 강의 영상 내 아래의 타임라인에서 학습할 수 있습니다.
- 절차적 생성 방식을 통한 맵 관리하기: 00:33:49
<br>

## 학습 목표
- 무한히 맵을 늘려나가는 절차적 맵 생성의 개념과 실무적인 필요성을 이해합니다.
- 맵을 일정한 조각(청크) 단위로 나누고, 각 청크의 시작 층수와 끝 층수 데이터를 매칭하여 자연스럽게 맵을 이어 붙이는 논리를 학습합니다.
- 스크립트를 통해 무한히 맵을 생성하며, 바닥 타일 스폰 지점에 새로운 바닥 타일 엔티티를 생성하는 방법을 구현합니다.
<br>

## 해당 영상 시청 후 수행해 볼 내용
- DataSetLogic내에 관리되는 층수 관리 테이블에 데이터를 추가하여 새로운 타일 정보를 추가합니다.
- 조건에 맞는 다음 타일셋이 무작위로 선택되어 마지막 끝 X좌표에 정확히 스폰되는지 플레이 버튼을 눌러 확인합니다.
- 생성된 맵의 발판 높낮이가 어색하지 않은지, 타일 사이에 빈틈이 발생하지 않는지 인게임에서 직접 테스트해 봅니다.
<br>

## 절차적 맵 생성의 개념 이해
- 절차적 맵 생성이란, 지형을 처음부터 끝까지 수작업으로 배치하는 대신 정해진 규칙과 알고리즘에 따라 게임 플레이 도중 실시간으로 맵을 만들어 내는 시스템을 의미합니다.
- 끝없이 달려야 하는 무한 러닝 장르에서 맵의 길이를 제한 없이 연장하고, 매번 다채로운 지형 패턴을 생성하기 위해 필요한 핵심 기반 기술입니다.
<br>

### 무한한 맵의 한계 극복
- 러닝 플랫포머 게임에서 플레이어가 달릴 맵을 에디터 상에 처음부터 끝까지 길게 만들어 두는 것은 작업량뿐만 아니라 시스템 메모리 측면에서도 큰 한계를 가집니다.
- 이를 해결하기 위해 게임 플레이가 진행되는 상황에 맞추어 실시간으로 새로운 맵 조각을 생성해 내는 '절차적 생성' 기법을 도입합니다.
- 이 기법을 적용하면 달리는 기차의 바로 앞에 선로를 계속 깔아주는 것처럼, 맵을 무한히 연장하면서도 시스템 자원을 효율적으로 관리할 수 있습니다.
<br>

### 타일셋(청크) 단위의 분할 관리와 무작위성
- 맵을 실시간으로 생성할 때 픽셀이나 타일 하나하나를 무작위로 찍어내는 것이 아니라, 일정한 길이의 맵 조각(청크)들을 여러 패턴으로 미리 제작해 두고 관리합니다.
- 스크립트가 이 미리 만들어진 조각들 중 하나를 규칙에 맞게 무작위로 선택하여 이전 조각의 끝부분에 레고 블록처럼 조립하는 방식으로 동작합니다.
- 이를 통해 맵의 구조적인 안정성을 유지하면서도, 유저가 게임을 플레이할 때마다 매번 다른 형태의 지형을 마주하게 만들어 게임의 리플레이성을 크게 높일 수 있습니다.
<br>

### DataSet에 각 바닥 타일 데이터 등록하기
<p align = "Center">
<img src ="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Running/MSW-100_Running_4_006.png" alt="MSW-100_Running_4_006.png">
</p>

1. 실제로 저장된 DataSet(TileSetInfo)구조의 일부입니다.
2. DataSetLogic에서 어떠한 방식으로 테이블에 저장할지 나타낸 표입니다.

- 샘플 월드의 바닥 타일은 1층과 2층 두 가지로 제작되었습니다. 따라서 tileFloorInfoTable 역시 [1]과 [2] 두 개의 배열로 나누어 별도로 관리 및 접근합니다.

```lua
DataSetLogic의 tileFloorInfoTable 저장 코드

table tilesFloorInfoTable = {[1]={}, [2]={}}

void InitTileSetInfoTable()
{
    -- 타일 오브젝트와 관련된 데이터셋을 저장하기 위한 메서드입니다.

    -- 월드스페이스에 저장된 데이터셋의 이름을 로컬로 접근하기 위한 변수입니다.
    local dataSetName = "TileSetInfo"

    -- 대상 데이터셋의 Row수입니다.
    local rowCount = self:GetDataSetRowCount(dataSetName)

    -- 타일셋 종류 수를 저장합니다.
    self.totalTileSetCount = rowCount

    -- 각 줄의 데이터를 담기 위한 변수입니다.
    local rowData

    -- 1 부터 데이터셋의 Row수만큼 순회를 시작합니다.
    for i = 1 , rowCount , 1 do
        rowData = 
        {
            -- 타일셋 오브젝트의 첫번째 타일의 층수입니다.
            FirstFloor = tonumber(_DataService:GetCell(dataSetName,i,"FirstFloor")),
            -- 타일셋 오브젝트의 마지막 타일의 층수입니다.
            LastFloor = tonumber(_DataService:GetCell(dataSetName,i,"LastFloor")),
            -- 타일셋 오브젝트를 생성하기 위한 원본 엔티티 모델(프리팹)Id입니다.
            EntryID = _DataService:GetCell(dataSetName,i,"EntryID")
        }

        -- rowData로 저장한 데이터들을 테이블에 저장합니다.
        self.tileSetInfoTable[i] = rowData
        
        -- 지금 등록한 타일셋의 층수를 변수로 저장합니다.
        local firstTileFloor = self.tileSetInfoTable[i].FirstFloor
        
        -- /분기1/ 만약 첫번째 타일 층수가 1층이라면
        if firstTileFloor == 1 then
            -- 1층 테이블 목록에 저장합니다.
            table.insert(self.tilesFloorInfoTable[1],i)
        -- /분기2/ 첫번째 타일 층수가 1층이 아니라면
        else
            -- 2층 테이블 목록에 저장합니다.
            table.insert(self.tilesFloorInfoTable[2],i)
        end
    end
}

number GetDataSetRowCount(string Name)
{
    -- 대상 데이터셋의 Row수를 반환합니다.

    -- 매개변수1 string Name : 대상 데이터셋의 이름을 전달받습니다.

    -- 확인한 데이터셋의 Row수를 반환합니다.
    return _DataService:GetRowCount(Name)
}
```

### DataSet에 등록된 각 바닥 타일 데이터 활용하기
- 저장된 tilesFloorInfoTable의 각 층별 테이블은 다음과 같이 분류할 수 있습니다.
  - tilesFloorInfoTable[1] : 1층부터 시작하는 바닥 타일셋 번호들이 담긴 테이블
  - tilesFloorInfoTable[2] : 2층부터 시작하는 바닥 타일셋 번호들이 담긴 테이블
- 마지막으로 생성된 바닥 타일의 끝 지점의 층수를 확인하고 각 층별 테이블 내에서 무작위 타일번호를 추출합니다.
- 마지막 타일의 층수를 등록하는 방법은 마지막으로 스폰하는 타일셋의 lastFloor값을 갱신합니다.

```lua
ScrollingController의 타일을 생성하는 메서드의 일부

number lastTileFloor

void SpawnTile(number tileSetNumber)
{
    -- 오브젝트 풀로부터 '매개변수'번의 타일 오브젝트를 전달받습니다.
    local spawnedTile = _ObjectPoolLogic:GetTile(tileSetNumber)

    -- 오브젝트 풀로부터 스폰받은 타일셋의 끝나는 지점의 층수를 기록합니다.
    self.lastTileFloor = _DataSetLogic.tileSetInfoTable[tileSetNumber].LastFloor
}
```

### 여러 청크맵 이동원리
<p align = "Center">
<img src ="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Running/MSW-100_Running_4_007.gif" alt="MSW-100_Running_4_007.gif">
</p>

- 월드 내에서 실제로 이동만 담당하는 Scrolling의 자식 엔티티 TileParent입니다.
- 각 청크맵 타일셋 엔티티별로 각자 이동을 수행하는 것이 아닌, 실제로 이동을 수행하는 TileParent의 자식 엔티티로 등록하여 자동으로 이동을 수행하도록 제작되어 있습니다.
- 즉, TileParent는 본격적인 게임 시작 시 -x축(오른쪽에서 왼쪽으로) 지속적으로 이동하게되며 TileParent엔티티의 자식으로 등록할 경우 자동으로 자식 엔티티 또한 동일하게 이동하게 됩니다.
<br>

### TileParent엔티티의 자식으로 등록하기
<p align = "Center">
<img src ="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Running/MSW-100_Running_4_008.png" alt="MSW-100_Running_4_008.png">
</p>

- EntityService를 통해서 하이어라키상에 있는 엔티티를 가져올 수 있습니다.
- 대상 엔티티의 Entity ID를 가져오기 위해선 하이어라키상에 배치된 엔티티를 우클릭 후 Copy Entity ID를 통해 ID값을 복사할 수 있습니다.
- SpawnService의 SpawnByModelId 메서드는 4번째 매개변수(Parameter)로 생성될 객체의 부모(Parent) 엔티티를 지정할 수 있습니다.
- 생성했던 바닥 타일셋 모델로부터 새로운 엔티티를 생성할 때 Parent를 설정합니다.
<br>

```lua
SpawnService의 SpawnByModelId 메서드 활용예시

void SpawnTile()
{
    // DataSetLogic으로부터 2번 청크맵 타일의 EntryID가져오기
    local entryID = _DataSetLogic.tileSetInfoTable[2].EntryID

    // 생성될 새로운 엔티티의 이름
    local entityName = "TempEntity"

    // 생성될 좌표값
    local spawnPosition = Vector3(50,0,0)

    // 새로 생성되는 엔티티의 부모 엔티티
    local tileParentEntity = _EntityService:GetEntity("d24b5917-1821-4743-ae07-77cc9bfc2d0a")

    _SpawnService:SpawnByModelId(entryID,entityName,spawnPosition,tileParentEntity)
}
```

### Tile과 상호작용하는 DeadZone 제작하기
<p align = "Center">
<img src ="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Running/MSW-100_Running_4_010.png" alt="MSW-100_Running_4_010.png">
</p>

- 바닥 타일이 제거되는 상황을 플레이어에게 보이지 않도록 하기 위해 카메라 영역으로부터 먼 거리에 새로운 엔티티를 생성합니다.
<br>

<p align = "Center">
<img src ="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Running/MSW-100_Running_4_011.png" alt="MSW-100_Running_4_011.png">
</p>

1. TileDeadZone 역할을 수행할 엔티티에 TriggerComponent를 등록합니다.
2. 부착된 TriggerComponent의 Collider의 Edit버튼을 통해 충돌 감지범위를 설정합니다.
<br>

<p align = "Center">
<img src ="https://develrocket-bucket.s3.ap-northeast-2.amazonaws.com/learning/MSW-100/Running/MSW-100_Running_4_012.png" alt="MSW-100_Running_4_012.png">
</p>

1. TileDeadZone 컴포넌트 스크립트를 생성하고 TileDeadZone에 등록합니다.
2. TileDeadZone의 Plain Text로 코드 내용을 등록합니다.
<br>

```lua
@Component
script TileDeadZone extends Component

property number discript = 0 -- 타일 오브젝트의 파괴(비활성)를 담당하는 컴포넌트입니다.

property PhysicsColliderComponent collider = nil

@ExecSpace("ClientOnly")
method void ConnectRefs()
-- 내부에 필요한 멤버들의 참조를 연결합니다.

-- 충돌체 감지를 수행하기 위한 PhysicsCollider 컴포넌트를 연결합니다.
self.collider = self.Entity.PhysicsColliderComponent
end

@ExecSpace("ClientOnly")
method void Init()
-- TileDeadZone 컴포넌트 초기화를 진행하는 메서드입니다.

-- 변수로 선언된 참조 연결을 수행합니다.
self:ConnectRefs()
end

@ExecSpace("ClientOnly")
method void OnBeginPlay()
-- 월드 실행시 호출되는 메서드입니다.

-- 해당 컴포넌트 초기화를 진행합니다.
self:Init()
end

@EventSender("Self")
handler HandleTriggerEnterEvent(TriggerEnterEvent event)
-- 트리거 충돌을 감지했을 때 발생되는 이벤트입니다.

-- 트리거 충돌의 엔티티를 저장합니다.
local TriggerBodyEntity = event.TriggerBodyEntity
-- 충돌된 트리거의 Collision그룹의 id 값을 확인합니다.
local TriggerGroup = tostring(TriggerBodyEntity.TriggerComponent.CollisionGroup.Id)

-- Config에 등록한 테이블에 key 값으로 위의 그룹 id값을 대입했을때 반환받는 문자열이 'Ground' 라면
-- 즉, 트리거로 감지한 충돌체가 Ground 라면
if _Config.triggerGroup[TriggerGroup] == "Ground" then
	
	-- 타일셋 오브젝트 반환을 수행합니다.
	_ObjectPoolLogic:ReturnTile(TriggerBodyEntity.Parent)
	
	-- 스크롤링 컨트롤러에게 마지막 타일에 이어질 무작위 타일 생성을 호출합니다.
	_GameLogic.scrollingController:SpawnRandomTile()
end
end

end
```

## 최소 구현 기준
- 시작 층수와 끝 층수 매칭 데이터가 정확하게 동작하며, 타일 간 끊어짐이 없도록 구현합니다.
- 스크롤 이동 속도에 맞춰 새로운 맵 조각이 제때 생성되어, 캐릭터가 발판이 없어 맵 밖으로 추락하는 현상이 없도록 구현합니다.
<br>

## 응용 및 확장 방향
- 다양한 바닥 타일 모델(Model)을 등록하며 종류를 확장하거나 변경하여 난이도가 높은 맵 조각이 자주 등장하도록 무작위 생성 가중치를 조절해 볼 수 있습니다.
